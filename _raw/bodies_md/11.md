### HttpURLConnection

단순히 API URL 을 연결하여 호출하는 방식입니다. Java 기본 라이브러리 포함되어 있기 때문에 외부 라이브러리 불필요 합니다. (Java 기본 라이브러리 포함)
    
    
    URL url = new URL("https://www.example.com");
    HttpURLConnection con = (HttpURLConnection) url.openConnection();
    con.setRequestMethod("GET");
    
    int status = con.getResponseCode();
    if (status == HttpURLConnection.HTTP_OK) {
        // 응답 처리
        BufferedReader in = new BufferedReader(new InputStreamReader(con.getInputStream()));
        String inputLine;
        StringBuffer content = new StringBuffer();
        while ((inputLine = in.readLine()) != null) {
            content.append(inputLine);
        }
        in.close();
        System.out.println(content.toString());
    }

하지만, 간단한 장점 만큼 복잡한 구조의 요청처리에 어려움이 있고, 비동기 처리 지원이 부족합니다. 이를 보완해 나온것이 HttpClient 입니다.

### RestTemplate

Spring 프레임워크에서 3.0 부터 제공하는 고수준 REST 클라이언트입니다. RESTful 웹 서비스와의 통신을 단순화하기 위해 설계되었습니다. HttpClient와는 다르게 Rest에 최적화 되어 있어 Jackson JSON 라이브러리를 활용하여 HTTP 요청/응답 본문을 Java 객체로 자동 변환하여 요청 본문에 포함시켜 사용 할 수 있습니다.

#### **HttpComponentsClientHttpRequestFactory 이용**

Connection pool 과 같은 timeout 설정을 진행 할 수 있습니다.

*참고* : UriComponentsBuilder 는 Spring에서 제공하는 url를 가독성 있게 만들어주는 기능입니다.
    
    
     UriComponents uri = UriComponentsBuilder.fromHttpUrl(url).build();
     HttpComponentsClientHttpRequestFactory factory = new HttpComponentsClientHttpRequestFactory();
     
     factory.setConnectTimeout(connTimeout);
     factory.setReadTimeout(readTimeout);
    
     RestTemplate restTemplate = new RestTemplate(factory);

RestTemplate.class를 살펴보면 호출 메소드인 exchage()가 구현되어 있습니다. requestEntity를 넣기 위해서 HttpEntity(String , HttpHeaders) 객체를 생성하였습니다.

### WebClient

WebClient는 HTTP 요청을 생성하고 전송하는 다양한 메서드를 제공합니다. method() , uri(), bodyValue(), retrieve(), bodyToMono() 등 메소드를 조합하여 HTTP 요청을 생성하고 응답 할 수 있습니다.

####  ** Mono 타입**

Mono는 Reactive Streams API의 핵심 타입 중 하나로, 0개 또는 1개의 요소를 포함하는 비동기 스트림을 나타냅니다. WebClient에서 HTTP 응답을 받을 때, bodyToMono() 메서드를 사용하여 응답 본문을 Mono 타입으로 변환합니다. Mono 타입은 비동기적으로 값을 생성하고, 다양한 연산자를 사용하여 스트림을 변환하고 조합할 수 있습니다.

우선 config로서 Webclient 객체를 적용하였습니다.

            return  WebClient.builder().baseUrl(datahubUrl)

### *참고* Webflux vs WebClient

개인적으로 WebClient와 Webflux 가 헷갈려서 정리해 보았습니다.

**단일 요청 vs. 다중 요청/스트림:**

  * **WebClient:** 기본적으로 **단일 요청/응답** 방식입니다. 한 번에 하나의 HTTP 요청을 보내고 응답을 받습니다. 여러 요청을 보내려면 각 요청마다 WebClient를 호출해야 합니다.
  * **Flux:** **다중 요청/스트림** 처리를 지원합니다. 여러 개의 HTTP 요청을 순차적 또는 병렬적으로 보내고, 각 응답을 스트림 형태로 처리할 수 있습니다. 시간에 따라 순차적으로 발생하는 데이터를 처리하는 데 적합합니다.



  * **WebClient:** HTTP 클라이언트입니다. 외부 시스템과 HTTP 통신을 담당합니다. 비동기적으로 요청을 보내고 응답을 받을 수 있습니다.
  * **Flux:** 리액티브 스트림의 Publisher입니다. 시간에 따라 발생하는 데이터 흐름을 처리하고, 다양한 연산자를 통해 데이터를 변환하고 조합할 수 있습니다.



WebClient는 **HTTP 통신** 을 담당하고, Flux는 **데이터 흐름 처리** 를 담당합니다. 비유하자면, WebClient는 "편지를 배달하는 우체부"이고, Flux는 "편지를 분류하고 처리하는 우체국 시스템"과 같습니다.

WebClient를 사용하여 여러 HTTP 요청을 보낼 수는 있지만, 각 요청은 독립적으로 처리됩니다. Flux는 이러한 여러 요청을 하나의 흐름으로 묶어서 처리하고, 다양한 연산자를 사용하여 데이터를 변환하고 조합할 수 있습니다. 즉, Flux는 WebClient보다 더 상위 레벨에서 동작합니다.

특징 | CompletableFuture | WebFlux  
---|---|---  
스레드 관리 | 스레드 풀 기반 | 이벤트 루프 기반  
스레드 수 | 많음 | 적음  
블로킹/Non-blocking | 블로킹 | Non-blocking  
자원 효율 | 낮음 | 높음  
확장성 | 제한적 | 높음  
  
### 결론

  * **HttpClient (특히 버전 5 이상):** 비동기 HTTP 요청을 지원합니다. CompletableFuture를 사용하여 비동기적으로 요청을 보내고 응답을 처리할 수 있습니다. 이를 통해 blocking I/O 작업으로 인한 성능 저하를 방지하고 애플리케이션의 응답성을 향상시킬 수 있습니다.
  * **RestTemplate:** Spring 3.0에서 5.0까지는 비동기 요청을 직접 지원하지 않았습니다. 동기 방식으로 작동하기 때문에, 요청을 보내고 응답을 기다리는 동안 스레드가 blocking됩니다.
  * **Spring 5.0 이후 (WebClient):** Spring 5.0부터는 비동기, non-blocking 방식으로 작동하는 WebClient가 도입되었습니다. WebClient는 Reactive Streams API를 기반으로 구현되어 있으며, 비동기 및 스트리밍 방식으로 HTTP 요청/응답을 처리할 수 있습니다. **Spring 5.0 이후에는 RestTemplate 대신 WebClient를 사용하는 것이 권장됩니다.**
