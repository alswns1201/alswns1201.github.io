쿠키와 세션은 웹 통신의 근간을 이루는 HTTP 프로토콜과 연관이 있습니다.

HTTP는 크게 두 가지 중요한 특징을 가지고 있습니다.**비연결지향(Connectionless)** 과 **상태 정보 유지 안 함(Stateless)** 입니다.  


  * **비연결지향 (Connectionless):** 서버와 클라이언트가 대화를 한 번 나누면, 바로 "안녕~" 하고 연결을 끊어버려요. 다음 대화를 할 땐 다시 새로운 연결을 만들어야 하죠.
  * **상태정보 유지 안 함 (Stateless):** 방금 나눴던 대화 내용을 기억하지 못해요. 그래서 매번 "너 누구니?" 하고 새로 물어봐야 하는 상황이 생길 수 있습니다.



위와 같은 특징을 보완하기 위해서 나온 것이 쿠키/세션 의 개념 입니다. 

• 쿠키란 무엇인가?

• 세션이란 무엇인가?

• HttpSessionListener 를 이용한 관리 

### 쿠키(Cookie)란 무엇인가?

먼저 쿠기에 대해서 알아보겠습니다. 쿠키는 웹사이트에 접속할 때 인터넷 사용자의 컴퓨터에 자동적으로 만들어지는 임시파일입니다. 정확히는 웹사이트 접속 시 접속자의 개인장치에 다운로드 되고, 브라우저에 저장되는 작은 텍스트 파일인데요.

쿠키의 형태는 Key : Value의 String 형식으로 이루어져 있습니다.   
쿠키이름=쿠키값; Domain=도메인값; Path=경로값; Expires=GMT형식의만료일시코드

#### **쿠키 넣는방법.**

**java.servlet.http.Cookie 를 이용하여 사용 됩니다.** 이를 이용하여 Cookie를 생성 하고 나서는 반드시 HttpServletResponse에다가 Cookie를 저장해야한다.
    
    
    	private void setInitSessionCookie(HttpServletResponse response, HttpServletRequest request, String value, int val) {

#### 쿠키는 주로 3가지 목적을 위해 사용한다.

  1. **세션 관리(Session Management)**  
로그인, 사용자 닉네임, 접속 시간, 장바구니 등의 서버가 알아야할 정보들을 저장
  2. **개인화(Personalization)**  
사용자마다 다르게 그 사람에 적절한 페이지를 보여줄 수 있다.
  3. **트래킹(Tracking)**  
사용자의 행동과 패턴을 분석하고 기록

### 세션(Session) 이란 무엇인가?

세션은 웹 서버가 **클라이언트(웹 브라우저)의 상태 정보(예: 로그인 정보, 장바구니 내용 등)를 서버 측에 저장하고 관리** 하는 기술입니다. HTTP 프로토콜은 상태를 유지하지 않기 때문에(Stateless), 사용자의 연속적인 요청을 하나의 흐름으로 파악하기 어렵습니다. 세션은 이러한 한계를 극복하고 사용자별로 고유한 상태를 유지할 수 있도록 도와줍니다.

#### 세션은 어떻게 동작 할까요 ?

로그인으로 동작을 통해 확인해 보겠습니다. 처음 접속을 하며 로그인을 시도 할때 보통 세션을 구현합니다.  
  


1\. 로그인 시도시 세션아이디 를 생성하고 클라이언트에 전달합니다.  
( 전달시 쿠키를 이용해 세션값을 JSESSIONID 에 저장합니다.)

  1. **세션 ID 재전송 및 서버의 세션 식별:** 이후 사용자가 동일 웹사이트에 요청을 보낼 때마다, 브라우저는 저장된 세션 ID 쿠키를 HTTP 요청 헤더에 자동으로 포함하여 서버에 전송합니다.
  2. **서버의 상태 정보 활용:** 서버는 요청 헤더에 포함된 세션 ID를 확인하고, 이 ID를 키(key)로 사용하여 서버 측 세션 저장소에서 해당 사용자의 상태 정보(value)를 찾아 요청을 처리합니다.   
  
"이 사용자는 이미 로그인했군!" 또는 "장바구니에 이런 물건들이 담겨 있네!" 와 같이 사용자의 이전 상태를 파악하고 맞춤형 응답을 제공할 수 있습니다.

    }

### 결론 

  * **쿠키 :** 클라이언트에 저장되고, 클라이언트의 메모리를 사용하기 때문에 **서버 자원을 사용하지 않음**

#### **@WebListener , HttpSessionListener , HttpSessionAttributeListener**

web.xml 로 적용하는 대신 @WebListener 를 사용하면 됩니다. session 로그인 방식에서 아래 두가지 리스너를 사용하여 적용해 보았습니다.

  * HttpSessionListener : HttpSession 객체가 생성되거나 소멸될 때 발생
  * HttpSessionAttributeListener : HttpSession 객체에 속성이 추가, 삭제, 수정될 때 발생

#### **SessionConfig 구현 - sessionCreated**

웹 애플리케이션에서 현재 활성화된 모든 세션을 효과적으로 관리하고 싶을 때가 있습니다. 예를 들어, 현재 접속 중인 모든 사용자에게 공지사항을 전달하거나, 특정 조건에 맞는 세션을 찾아 강제로 종료시키는 등의 고급 기능을 구현하고자 할 때 유용합니다.  
  
ConcurrentHashMap 을 이용해서 HttpSession 과 다르게 서버의 모든 세션을 관리할수 있습니다. HttpSession이 담길때 마다 sessionCreated()를 통해서 put하여 적용하였습니다.
    
    
    private static final Map<String, HttpSession> sessions = new ConcurrentHashMap<>();
    
    
    @WebListener
    public class SessionConfig implements HttpSessionListener, HttpSessionAttributeListener {
    
    private static final Map<String, HttpSession> sessions = new ConcurrentHashMap<>();
       @Override
        public void sessionCreated(HttpSessionEvent httpSessionEvent) {
            sessions.put(httpSessionEvent.getSession().getId(), httpSessionEvent.getSession());
    
        }
    
    }

HttpSessionListener의 sessionCreated 메소드와 스레드 안전(thread-safe)한 ConcurrentHashMap을 사용하면 이러한 중앙 집중식 세션 관리를 비교적 간단하게 구현할 수 있습니다.
