### kind의 정의와 역할

kind는 Kubernetes IN Docker의 약자로 도커 컨테이너를 쿠버네티스 노드로 사용하여 클러스터를 실행하는 도구입니다. 가상 머신을 띄우지 않고 도커 엔진 위에서 실행되므로 로컬 환경에서 가볍고 빠르게 쿠버네티스 환경을 구축할 수 있습니다.

choco install kind

kind create cluster

### 클러스터의 개념

쿠버네티스 클러스터는 여러 대의 컴퓨터를 하나로 묶어 컨테이너화된 애플리케이션을 관리하는 시스템입니다.

  * 컨트롤 플레인: 클러스터의 전체 상태를 결정하고 관리하는 지휘소 역할을 합니다.
  * 노드: 실제 컨테이너들이 배치되어 실행되는 작업 공간입니다. kind 환경에서는 하나의 도커 컨테이너가 이 역할을 모두 수행합니다.

## 도커 기반 애플리케이션 이미지 생성

### JAR 파일의 이미지화

쿠버네티스는 실행 파일인 JAR를 직접 다루지 않고 컨테이너 단위로 관리합니다. 따라서 개발한 소스 코드를 JAR로 빌드한 뒤 이를 실행할 수 있는 자바 환경이 포함된 도커 이미지를 만들어야 합니다.

### Dockerfile 구성 요소

이미지를 생성할 때는 베이스 이미지를 설정하는 과정이 중요합니다. 컴파일된 클래스 파일 버전과 실행 환경의 자바 버전이 일치해야 하며 이번 실습에서는 자바 21 기반의 경량화된 리눅스 배포판을 베이스 이미지로 사용하였습니다.

Dokerfile 구성.
    
    
    FROM eclipse-temurin:21-jdk-alpine
    COPY math-0.0.1-SNAPSHOT.jar math-0.0.1-SNAPSHOT.jar
    ENTRYPOINT ["java", "-jar", "/math-0.0.1-SNAPSHOT.jar"]

## 쿠버네티스 객체 관리 및 설정

### Deployment와 Service YAML의 역할

쿠버네티스는 YAML 형식을 통해 원하는 상태를 정의합니다.

  * Deployment: 포드의 개수와 이미지 버전 등 애플리케이션의 배포 상태를 정의합니다. 포드가 비정상 종료되면 설정된 상태를 유지하기 위해 자동으로 새 포드를 생성합니다.
  * Service: 포드에 접근하기 위한 고정된 입구를 제공합니다. 포드는 생성될 때마다 내부 주소가 바뀌지만 서비스는 변하지 않는 주소를 제공하여 외부 통신을 가능하게 합니다.



Deployment.yaml 
    
    
    apiVersion: apps/v1
    kind: Deployment
    metadata:
      name: my-app-deployment
    spec:
      replicas: 2
      selector:
        matchLabels:
          app: my-app
      template:
        metadata:
          labels:
            app: my-app
        spec:
          containers:
            - name: my-app-container
              image: my-app:v1
              imagePullPolicy: Never
              ports:
                - containerPort: 8080

## 고가용성과 셀프 힐링

\- replicas :2

레플리카 설정의 핵심은 하나가 죽어도 서비스가 중단되지 않게 만드는 것입니다. 만약 포드 하나에 에러가 발생하여 종료되거나 노드에서 사라지면 쿠버네티스의 컨트롤 플레인은 설정된 개수보다 현재 포드가 부족하다는 것을 감지합니다. 이때 쿠버네티스는 자동으로 새로운 포드를 즉시 생성하여 전체 개수를 다시 2개로 맞춥니다. 이를 셀프 힐링이라고 부릅니다.

service.yaml
    
    
    apiVersion: v1
    kind: Service
    metadata:
      name: my-app-service
    spec:
      type: NodePort
      selector:
        app: my-app
      ports:
        - port: 80
          targetPort: 8080
          nodePort: 30001

### imagePullPolicy 옵션 상세

포드를 생성할 때 이미지를 어디서 가져올지 결정하는 정책입니다.

  * Never: 외부 저장소에서 이미지를 다운로드하지 않습니다. 로컬 도커에 빌드한 뒤 kind load 명령어로 클러스터 내부 노드에 직접 복사한 이미지만 사용하도록 강제할 때 사용합니다.
  * IfNotPresent: 노드 내부에 이미지가 존재하면 그것을 우선 사용하고 없을 때만 외부 저장소에서 이미지를 받아옵니다. 로컬 실습 환경에서는 이미지가 이미 로드되어 있다면 추가적인 네트워크 작업 없이 빠르게 포드를 생성할 수 있게 합니다.



kind 종류에는 Development. service 등이 존재하고 이를 한번에 묶어서 처리하는 Kustomization 이 존재한다.
    
    
    # kustomization.yaml
    apiVersion: kustomize.config.k8s.io/v1beta1
    kind: Kustomization
    
    # 실행할 파일 목록을 나열합니다.
    resources:
      - deployment.yaml
      - service.yaml
    
    # 모든 자원에 공통으로 적용할 설정을 정의할 수 있습니다 (선택 사항)
    commonLabels:
      project: my-first-k8s

project/   
├── deployment.yaml   
├── service.yaml   
└── kustomization.yaml

kubectl apply -k . 명령어를 통해서 Ksutomizaion으로 둘을 동시에 적용하여 진행한다.
