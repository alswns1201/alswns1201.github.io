JVM 메모리 구조는 크게 모든 스레드가 공유하는 영역과 스레드마다 별도로 생성되는 영역으로 나뉩니다.

각 영역의 역할은 다음과 같습니다.

**공유 영역 (모든 스레드가 공유)**

  * Method Area (Metaspace): 클래스 로더가 읽어들인 클래스의 메타데이터(필드, 메서드 정보, 런타임 상수 풀)와 static 변수를 저장합니다. Java 8부터는 PermGen 대신 네이티브 메모리 영역인 Metaspace가 이 역할을 담당합니다.
  * Heap: new로 생성된 객체 인스턴스가 저장되는 공간입니다. GC(Garbage Collection)의 주요 대상이며, 내부적으로 Young Generation(Eden, Survivor 0/1)과 Old Generation으로 나뉩니다. 새로 생성된 객체는 Eden에 할당되고, 여러 번의 GC에서 살아남은 객체가 Old Generation으로 이동합니다.



**스레드별 영역 (스레드마다 생성)**

  * Stack: 메서드가 호출될 때마다 하나의 Stack Frame이 생성되어 push되고, 메서드가 끝나면 pop됩니다. 각 프레임에는 지역 변수, 매개변수, 연산 중간값을 담는 오퍼랜드 스택이 포함됩니다. 스레드가 종료되면 이 영역도 함께 사라집니다.
  * PC Register: 현재 스레드가 실행 중인 JVM 명령의 주소를 가리킵니다. 스레드마다 별도로 필요한 이유는, 멀티스레드 환경에서 컨텍스트 스위칭이 일어날 때 각 스레드가 자신이 어디까지 실행했는지 기억해야 하기 때문입니다.
  * Native Method Stack: Java 코드가 아닌 네이티브 코드(C/C++로 작성된 JNI 메서드 등)를 호출할 때 사용되는 스택입니다.



관련 흔한 에러 

### StackOverflowError

Stack 영역에서 발생하는 에러입니다. 스레드마다 할당된 Stack 크기(기본값은 보통 512KB~1MB, JVM 옵션 -Xss로 조정 가능)를 초과해 Stack Frame이 쌓일 때 발생합니다.

가장 흔한 원인은 재귀 호출입니다. 종료 조건이 없거나 잘못된 재귀 함수는 메서드가 호출될 때마다 Stack Frame을 계속 push하다가 할당된 Stack 크기를 넘기는 순간 StackOverflowError를 던집니다.
    
    
    Exception in thread "main" java.lang.StackOverflowError
        at com.example.Recursive.call(Recursive.java:5)
        at com.example.Recursive.call(Recursive.java:5)
        at com.example.Recursive.call(Recursive.java:5)
        ...

스택 트레이스에 동일한 메서드 호출이 반복되는 패턴이 보이면 재귀 종료 조건을 먼저 의심하면 됩니다. -Xss 값을 늘려서 임시로 완화할 수는 있지만, 근본적으로는 재귀 깊이를 줄이거나 반복문으로 바꾸는 것이 정석입니다.

### OutOfMemoryError ( OOM ) 

Heap이나 Method Area 같은 공유 영역에서 더 이상 메모리를 할당할 공간이 없을 때 발생합니다. 발생 위치에 따라 메시지가 다르게 나타납니다.

  * java.lang.OutOfMemoryError: Java heap space: Heap 영역이 가득 찼는데 GC를 수행해도 공간을 확보하지 못할 때 발생합니다. 객체를 계속 참조하고 있어 GC 대상이 되지 못하는 메모리 누수, 또는 단순히 힙 크기(-Xmx)가 애플리케이션이 필요로 하는 양보다 작을 때 나타납니다.
  * java.lang.OutOfMemoryError: Metaspace: 클래스 메타데이터가 저장되는 Metaspace가 가득 찼을 때 발생합니다. 동적으로 클래스를 계속 생성하는 프레임워크(리플렉션 기반 프록시, 일부 스크립트 엔진 등)를 잘못 사용하거나 클래스로더 누수가 있을 때 자주 나타납니다.
  * java.lang.OutOfMemoryError: GC overhead limit exceeded: GC가 너무 자주 실행되는데도 회수되는 메모리가 거의 없을 때(기준: GC에 98% 이상의 시간을 쓰는데 회수되는 힙이 2% 미만) 발생합니다. Heap space 에러의 전조 증상으로 볼 수 있습니다.
