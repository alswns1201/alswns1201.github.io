서비스를 운영하다 보면 “특정 클라이언트가 너무 많은 요청을 보내는 상황”을 반드시 마주하게 된다.  
이런 과도한 요청은 서버 자원을 잠식하고, 다른 사용자의 응답 속도를 떨어뜨린다. 이를 막기 위해 **Rate Limiting(요청 제한)** 기법을 사용한다. 오늘은 그 중에서도 간단하고 강력한 라이브러리인 **Bucket4j** 를 이용한 구현 방법을 다룬다.

* * *

### 1\. Bucket4j란?

Bucket4j는 **토큰 버킷(Token Bucket)** 알고리즘을 기반으로 한 Java용 Rate Limiting 라이브러리다.  
한마디로, “일정 시간 동안 허용되는 요청 수를 제어하는” 도구다.

작동 원리는 간단하다.

  1. **버킷(bucket)** 에 일정량의 **토큰(token)** 이 들어 있다.
  2. 요청이 들어올 때마다 토큰을 하나씩 꺼낸다.
  3. 버킷이 비면 요청은 거부된다(HTTP 429 등).
  4. 일정 주기마다 토큰이 다시 채워진다(refill).



* * *

### 2\. Gradle 의존성 추가

먼저 build.gradle에 Bucket4j 의존성을 추가한다.

implementation 'com.github.vladimir-bukhtoyarov:bucket4j-core:8.7.0' 

(버전은 Maven Central에서 최신으로 확인 가능)

* * *

### 3\. Rate Limiting 설정 파일

이제 실제 설정 클래스를 보자.
    
    
    @Configuration
    public class Bucket4jConfig {
    
    
        //1초당 10회 요청 제한당
        @Value("${bucket.capacity}")
        private int capacity;
    
        @Value("${bucket.refill.tokens}")
        private int refillTokens;
    
        @Value("${bucket.refill.duration.seconds}")
        private int refillDuration;
    
    
        @Bean
        public Bucket bucket() {
            Refill refill = Refill.intervally(
                    refillTokens,
                    Duration.ofSeconds(refillDuration));
    
            Bandwidth limit = Bandwidth.classic(capacity, refill);
    
            return Bucket.builder()
                    .addLimit(limit)
                    .build();
        }
    }

* * *

### 4\. 설정값 (application.yml)

@Value로 주입받는 속성들을 application.yml에 정의한다.
    
    
    #bucket count
    bucket.capacity=10
    bucket.refill.tokens=10
    bucket.refill.duration.seconds=1

bucket: capacity: 10 # 버킷 최대 토큰 수 (요청 허용량) , refill: tokens: 10 # 매번 충전되는 토큰 수 , duration: seconds: 1 # 몇 초마다 충전할지 

이 설정은 “**1초당 10회 요청 허용** ”을 의미한다. 즉, 초당 10회 이상 요청이 들어오면 이후 요청은 모두 거부된다.

* * *

### 5\. 실제 사용 (예시 Controller)

Bucket은 간단히 주입받아서 사용할 수 있다.  
요청이 들어올 때마다 토큰을 하나씩 꺼내고, 없으면 429 에러를 반환하도록 하면 된다.
    
    
    @RestController
    @RequestMapping("/api")
    @RequiredArgsConstructor
    public class ApiController {
    
        private final Bucket bucket;
    
        @GetMapping("/data")
        public ResponseEntity<String> getData() {
            if (bucket.tryConsume(1)) {
                return ResponseEntity.ok("정상 요청");
            } else {
                return ResponseEntity.status(HttpStatus.TOO_MANY_REQUESTS)
                        .body("요청 한도를 초과했습니다. 잠시 후 다시 시도해주세요.");
            }
        }
    }

* * *

### 6\. 작동 원리 정리

개념설명  **capacity** | 버킷의 최대 크기 (토큰 수)  
---|---  
**refillTokens** | 리필 시 채워질 토큰 개수  
**refillDuration** | 리필 주기 (초 단위)  
**tryConsume(n)** | n개의 토큰을 소비 (성공 시 true, 실패 시 false)  
  
Bucket4j는 스레드 세이프하며, 분산 환경에서도 Redis 등과 연동 가능하다.  
단일 인스턴스 기준에서는 위 코드만으로 충분하다.

* * *

### 7\. 정리

  * Bucket4j는 **단순하고 효율적인 요청 제한 도구** 다.
  * Refill로 토큰 리필 주기를, Bandwidth로 전체 제한 규칙을 설정한다.
  * Controller나 Filter 단에서 tryConsume() 호출만으로 간단히 요청 제어 가능하다.
  * 대규모 환경에서는 Redis 백엔드와 함께 분산 Rate Limit도 구현할 수 있다.
