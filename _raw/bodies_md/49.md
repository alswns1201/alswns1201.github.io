## 1\. 들어가며

서비스가 커질수록 Controller나 Service 단에서 비슷한 로그를 반복적으로 남기게 됩니다.  
“요청이 들어왔는가?”, “정상적으로 리턴됐는가?”, “예외가 발생했는가?” — 이런 공통 관심사(Cross Cutting Concern)를 매번 직접 코드로 작성하면 유지보수성이 떨어집니다.

이런 반복 작업을 깔끔하게 처리해주는 게 바로 **AOP(Aspect Oriented Programming)** 입니다.

* * *

## 2\. AOP의 핵심 개념 정리

용어의미  **Aspect** | 공통 관심사를 모듈화한 클래스 (@Aspect로 정의)  
---|---  
**Join Point** | 메서드 실행 시점 같은 AOP가 적용될 수 있는 지점  
**Pointcut** | 실제로 AOP를 적용할 구체적인 메서드 선택 조건  
**Advice** | 실행 전(@Before), 후(@AfterReturning), 예외(@AfterThrowing), 전체(@Around) 시점에 수행되는 코드 블록  
  
* * *

## 3\. Controller 단 공통 로그: LoggingAspect

Controller에서 요청 진입, 정상 반환, 예외 발생을 각각 기록하도록 구성합니다.
    
    
    @Aspect
    @Component
    public class LoggingAspect {
    
        private static final Logger logger = LoggerFactory.getLogger(LoggingAspect.class);
    
        @Before("@within(org.springframework.web.bind.annotation.RestController)")
        public void logBefore(JoinPoint joinPoint) {
            logger.info("[ENTER] {}.{}()",
                    joinPoint.getSignature().getDeclaringTypeName(),
                    joinPoint.getSignature().getName());
        }
    
        @AfterReturning(pointcut = "@within(org.springframework.web.bind.annotation.RestController)", returning = "result")
        public void logAfterReturning(JoinPoint joinPoint, Object result) {
            logger.info("[RETURN] {}.{}() => {}",
                    joinPoint.getSignature().getDeclaringTypeName(),
                    joinPoint.getSignature().getName(), result);
        }
    
        @AfterThrowing(pointcut = "@within(org.springframework.web.bind.annotation.RestController)", throwing = "ex")
        public void logAfterThrowing(JoinPoint joinPoint, Throwable ex) {
            logger.error("[EXCEPTION] {}.{}() => {}",
                    joinPoint.getSignature().getDeclaringTypeName(),
                    joinPoint.getSignature().getName(), ex.getMessage(), ex);
        }
    }

**핵심 포인트**

  * @within(RestController) : 클래스 레벨에 @RestController가 붙은 모든 메서드에 적용
  * JoinPoint : 실행 중인 메서드의 정보(클래스명, 메서드명 등)에 접근
  * @AfterThrowing : 예외가 발생했을 때만 동작



이 코드 하나로 모든 Controller 메서드의 입출력 흐름을 한눈에 추적할 수 있습니다.

## 4\. Service 단 세밀 제어: 커스텀 어노테이션 기반 AOP

Controller는 공통 로깅만으로 충분하지만,  
Service 레이어에서는 상황에 따라 **반환값 로그 여부, 요청 ID 연동, Trace 관리** 등을 다르게 처리해야 할 때가 있습니다.

이럴 때는 커스텀 어노테이션을 정의해 AOP를 유연하게 적용할 수 있습니다.

### 4-1. 커스텀 어노테이션 정의
    
    
    @Retention(RetentionPolicy.RUNTIME)
    @Target({ElementType.METHOD})
    public @interface MethodLogging {
        boolean isLoggingValue() default false;
    }

* * *

### 4-2. AOP 구현
    
    
    @Aspect
    @Component
    @Slf4j
    public class MethodLoggingAspect {
    
        @Around("@annotation(com.kbInsure.healthReport.common.aop.MethodLogging) && @annotation(aop)")
        public Object methodLoggingAround(ProceedingJoinPoint joinPoint, MethodLogging aop) throws Throwable {
    
            String requestId = null;
    
            try {
                HttpServletRequest request = ((ServletRequestAttributes) RequestContextHolder.getRequestAttributes()).getRequest();
                HttpServletResponse response = ((ServletRequestAttributes) RequestContextHolder.getRequestAttributes()).getResponse();
                requestId = response.getHeader("X-B3-TraceId");
                log.info("Req ID:[{}] URL:[{}] Params:[{}]",
                        requestId, request.getRequestURI(),
                        Arrays.stream(joinPoint.getArgs())
                                .map(String::valueOf)
                                .collect(Collectors.joining(", ")));
            } catch (Exception e) {
                log.warn("Failed to extract trace info: {}", e.getMessage());
            }
    
            try {
                Object proceed = joinPoint.proceed();
    
                if (aop.isLoggingValue()) {
                    log.info("Res ID:[{}] Value:[{}]", requestId, proceed);
                }
    
                return proceed;
            } catch (Exception e) {
                log.error("Error after ID:[{}] message:[{}]", requestId, e.getMessage());
                throw e;
            }
        }
    }

**핵심 포인트**

  * @Around : 메서드 실행 전/후 모두 제어 가능
  * @annotation(aop) : 실제 선언된 @MethodLogging의 속성값(isLoggingValue)을 가져옴
  * joinPoint.proceed() : 실제 비즈니스 메서드를 실행



* * *

### 4-3. 실제 사용 예시
    
    
    @MethodLogging(isLoggingValue = true)
    public UserResponse getUserInfo(Long userId) {
        return userService.findById(userId);
    }

필요한 메서드에만 세밀하게 로깅을 붙일 수 있습니다.  
로그 출력 여부나 trace 연동도 각 상황에 맞게 조절 가능합니다.

* * *

## 5\. 마무리

AOP를 이용하면 "공통된 일"을 한 곳에서 처리할 수 있습니다.  
로깅, 인증 체크, 트랜잭션 처리 등 여러 곳에서 반복되는 코드를 줄이고,  
핵심 비즈니스 로직에만 집중할 수 있게 해줍니다.

Controller에는 공통 진입 로그를,  
Service에는 세밀한 제어 로그를 — 이런 식으로 계층별로 다르게 적용하면  
가시성과 유지보수성을 모두 챙길 수 있습니다.
