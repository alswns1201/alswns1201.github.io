# ✅ **단방향 암호화 (Hashing)**

말 그대로 **한 방향으로만** 가는 암호화.  
**한 번 암호화하면 원래 값으로 절대 복구 못함.**

대표적인 것들:

  * SHA-256
  * bcrypt
  * scrypt
  * Argon2



### ✔️ 특징

  * 원본 → 암호문 O
  * 암호문 → 원본 X
  * 비밀번호 저장에 쓰는 이유: 해킹돼도 원본을 알 수 없음
  * 같은 입력이면 기본적으로 같은 출력이지만, 비밀번호용은 salt를 써서 매번 다르게 만듦



### ✔️ 언제 쓰냐?

비밀번호, 토큰 검증, 무결성 체크 같은 "복구 필요 없는 데이터"에 씀.

# ✅ **양방향 암호화 (Encryption)**

**암호화된 값을 다시 복호화할 수 있어야 하는 경우.**  
원본을 살려야 하니까 key(비밀키)를 반드시 갖고 있어야 함.

종류는 두 가지 스타일이 있음:

## 1) 대칭키 암호화 (Symmetric)

  * AES-256
  * 한 개의 키로 **암호화 = 복호화** 둘 다 가능
  * 빠르고 실용적



## 2) 비대칭키 암호화 (Asymmetric)

  * RSA, ECC
  * 공개키(public key) → 암호화
  * 개인키(private key) → 복호화
  * 인증서, 공개키 기반 구조(PKI)에 사용



### ✔️ 특징

  * 원본 ↔ 암호문 상호 변환 가능
  * 키 관리가 핵심



### ✔️ 언제 쓰냐?

주민번호, 계좌번호처럼 **복구가 필요한 민감정보** 저장할 때.  
또는 HTTPS 통신, JWT 서명 검증(RSA) 같은 인증 흐름.

# 🔥 **한 줄로 정리**

  * **단방향:** 되돌릴 수 없음. 비밀번호 같은 걸 저장할 때.
  * **양방향:** 다시 평문으로 꺼내야 할 때. 키가 필요함.
