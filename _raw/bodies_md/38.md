> springboot 작업을 하다가 단순히 actuator 의 기능에 대해서 궁금하였고  
> 더 확장해보고 prometheus를 실행해보고 Grafana로 시각화해서 보고 싶어 시작되었다.

🧑‍💻 개발환경

  * 다행히 Desktop에서 Docker 를 계속 사용하였기 때문에 Prometheus와 Grafana에 대한 image는 쉽게 다운 받아서 구동 시킬수 있었다.
  * spring boot 환경에서 단순히 비동기 멀티쓰레드 api 하나를 날려보고 확인해보고 싶었다.
  * 내가 확인 해보고 싶었던 것은 Pool로 관리했을때 진짜 Pool에 들어있는 개수 만큼 만 가지고 활용하는지 , 그거에 대한 문제는 없는지 시각적으로 보고 싶었다.



## DeskTop docker 이용

  * springboot 의존성


    
    
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
    
    // Prometheus 의존성 (Micrometer)
    implementation 'io.micrometer:micrometer-registry-prometheus'
    

## prometheous.yml 생성
    
    
    global:
      scrape_interval: 15s#메트릭 수집 주기 (15초마다 수집)
    
    scrape_configs:
      - job_name: 'spring-boot-app'
        metrics_path: '/actuator/prometheus'
        static_configs:
          - targets: ['host.docker.internal:8080']# Spring Boot애플리케이션이 실행되는 주소

  * docker 에서 prometheus 실행



docker run -d -p 9090:9090 -v /c/project/batch/prometheus.yml:/etc/prometheus/prometheus.yml prom/prometheus

## Prometheus 데이터 소스 추가

Grafana에 로그인 후, 왼쪽 메뉴에서 Configuration (기어 아이콘) > Data Sources를 선택합니다.  
Connections - Data sources

  * Add data source를 클릭하고, Prometheus를 선택합니다.
  * Prometheus URL에 <http://host.docker.internal:9090> 을 입력합니다.  
(yml 파일에서 설정한 springboot 경로 입니다)  
host.docker.internal은 Docker에서 호스트 시스템에 접근할 수 있도록 하는 특수한 주소입니다.
  * Save & Test 버튼을 클릭하여 연결을 확인합니다.



## 그라파나 실행

Grafana는 Prometheus 데이터를 시각화하는 데 사용됩니다. Grafana를 Docker로 실행하려면 다음 명령어를 사용합니다.

docker run -d -p 3000:3000 grafana/grafana

**Grafana에 Prometheus 데이터 소스 추가**

  * Grafana 웹 UI에 로그인하려면 http://localhost:3000으로 이동합니다.
  * 기본 로그인 정보는 admin/admin입니다. 첫 로그인 시 비밀번호를 변경해야 할 수 있습니다.
  * 로그인 후 **Configuration** > **Data Sources** 에서 **Prometheus** 를 추가하고, Prometheus URL을 <http://host.docker.internal:9090>으로 설정합니다.
  * **Save & Test**를 클릭하여 연결을 확인합니다.



### Grafana 대시보드 생성

Create Dashboard를 클릭합니다. new Dashboard  
Add Query에서 Prometheus를 선택하고, 원하는 메트릭을 입력합니다.  
예시: jvm_memory_bytes_used (JVM 메모리 사용량)  
원하는 시각화를 추가하고 대시보드를 완성합니다.

**Grafana 에서 적용 관련 매트릭 설명(기능)**  
CPU 사용량 메트릭  
process_cpu_usage: 전체 프로세스의 CPU 사용률을 측정하는 메트릭입니다.  
스레드 상태 메트릭  
jvm_threads_daemon: 데몬 스레드 수  
jvm_threads_live: 현재 실행 중인 스레드 수  
jvm_threads_peak: 애플리케이션에서 생성된 최고 스레드 수

## 실제 확인

구현된 API 를 날리기 전에는 기존 Thread 개수를 유지하다가.

private ExecutorService executorService = Executors.newFixedThreadPool(4);

를 통해서 4개만 생성되어 4개로 모든 api의 처리가 진행 되었다.  
(기존 spring boot 구동 및 api 와 상관 없는 thread 제외 )
