## 1\. 전체 데이터 흐름 이해

현재 구성하시려는 흐름은 다음과 같습니다. 데이터가 파이프라인을 타고 흐르는 구조

  1. **Source DB** : 원본 데이터가 있는 곳.
  2. **Source Connector** : DB의 변화를 감지해 Kafka 토픽(my_topic_users)으로 데이터를 쏴줍니다. (완료됨)
  3. **Kafka Topic (my_topic_users)** : 중간 저장소 역할을 합니다.
  4. **Sink Connector** : 토픽을 구독하고 있다가, 새로운 메시지가 오면 **Target DB에 테이블을 만들고 데이터를 입력** 합니다. (지금 할 작업)
  5. **Target DB** : 최종적으로 데이터가 쌓이는 곳.



## 2\. Sink Connector 설정 핵심 옵션

자동으로 테이블을 생성하게 하려면 설정 파일(JSON)에 다음 두 가지 옵션이 반드시 포함되어야 합니다.

  * **auto.create: "true"** : 목적지 DB에 테이블이 없으면 토픽의 스키마를 바탕으로 테이블을 생성합니다.
  * **insert.mode: "upsert" 또는 "insert"** : 데이터를 어떻게 넣을지 결정합니다. (upsert를 쓰려면 pk.mode 설정이 추가로 필요합니다.)



## 3\. Sink Connector 등록하기 (REST API)

kafka-connect 컨테이너(포트 8083)에 아래와 같이 POST 요청을 보내 Sink를 등록합니다. MySQL로 데이터를 보낸다고 가정했을 때의 예시입니다.

아래 내용을 body를 통해서 / connectors 에 post를 적용하여 확인.
    
    
    {
      "name": "my-mariadb-sink-connector",
      "config": {
        "connector.class": "io.confluent.connect.jdbc.JdbcSinkConnector",
        "tasks.max": "1",
        "topics": "my_topic_users",
        "connection.url": "jdbc:mysql://host.docker.internal:3306/mydb",
        "connection.user": "spring",
        "connection.password": "spring123",
        "auto.create": "true",    
        "auto.evolve": "true",    
        "delete.enabled": "false",
        "insert.mode": "upsert",
        "pk.mode": "record_value",
        "pk.fields": "id",
        "table.name.format": "users_sink",
        "key.converter": "org.apache.kafka.connect.json.JsonConverter",
        "key.converter.schemas.enable": "true",
        "value.converter": "org.apache.kafka.connect.json.JsonConverter",
        "value.converter.schemas.enable": "true"
      }
    }

users_sink 테이블이 없었다가. insert로 db가 들어오면 consumer에서 반응하여 topic에 적용되고 , 해당 topic을 sink가 반응하여

users_sink 테이블을 (없다면 생성) 이용하여 데이터가 들어가는것을 확인.
