"Oracle JDK는 유료다"라는 말은 반은 맞고 반은 틀리다. 정확히는 **Java 언어와 문법을 쓰는 건 항상 무료**고,
유료/무료가 갈리는 지점은 그걸 컴파일하고 실행하는 **런타임(JDK/JVM) 배포판을 어디서 받았고 어떤 라이선스로
받았는가**다. 이 구분을 모르면 사이드 프로젝트에서 쓰던 설정을 회사 프로젝트에 그대로 가져갔다가
라이선스 감사(audit)에서 걸리는 상황이 생길 수 있다.

## JDK 안에 뭐가 들어있나

JDK(Java Development Kit)는 컴파일러, 디버깅 도구 같은 개발 도구에 JRE(실행 환경)와 JVM(가상머신)까지
번들로 포함한 패키지다. JVM이 JDK 안에 같이 배포되기 때문에 실무에서는 보통 JDK와 JVM을 묶어서 말한다.

## 라이선스가 왜 이렇게 복잡해졌는가: 타임라인

- **Sun Microsystems 시절**: 기본적으로 무료. 상업 지원이 필요할 때만 별도 계약.
- **2010년 Oracle 인수 이후**: 한동안 기존 정책 유지.
- **BCL(Binary Code License) 시대**: 개발/테스트는 무료, **상업적 배포에는 유료 라이선스** 필요. 이 시점부터
  기업들이 OpenJDK로 눈을 돌리기 시작했다.
- **OTN(Oracle Technology Network) 라이선스**: 개인/개발/테스트/데모 용도는 무료, 상업 배포는 여전히 유료.
- **NFTC(No-Fee Terms and Conditions), JDK 17부터**: 상업적 용도를 포함해 대부분의 경우 무료. 다만
  **LTS 기간 이후의 업데이트나 특정 Oracle 제품/서비스 연동 시**에는 여전히 유료 라이선스가 필요할 수 있다.

즉 "요즘은 무료다"로 끝내면 안 되고, **몇 버전을 쓰는지, LTS 지원 기간이 언제 끝나는지**까지 확인해야
정확한 판단이 된다. JDK 17 NFTC라고 해서 영구히 무료라는 뜻이 아니라, "LTS 기간 동안은" 무료라는 조건이
붙어 있다.

## 그래서 실무에서는 뭘 선택해야 하나

라이선스 문제를 원천적으로 피하는 방법은 **OpenJDK 기반 빌드**를 쓰는 것이다. OpenJDK 프로젝트 자체는
소스 코드만 제공하고, 실제로 설치해서 쓰는 바이너리는 Eclipse Temurin(구 AdoptOpenJDK), Azul Zulu,
Amazon Corretto, Red Hat build of OpenJDK 같은 벤더가 빌드해서 배포한다. 이 벤더들은 OpenJDK 소스를
그대로 빌드하고 테스트해서 제공하기 때문에, Oracle JDK와 기능적으로 동일하면서 라이선스 리스크가 없다.

IntelliJ에서 [Project Settings] → [Platform Settings] → JDK 다운로드 메뉴에 뜨는 선택지들이
사실 이 벤더 목록이다 — "어디서 받을지"가 곧 "어떤 라이선스로 쓸지"를 결정한다는 걸 알고 고르는 것과
모르고 아무거나 받는 것은 다르다.

## 판단 체크리스트

- 지금 프로젝트가 **상업적 배포**인가, 개발/테스트용인가?
- Oracle JDK를 쓴다면 **몇 버전이고 LTS 지원 기간이 언제 끝나는가**?
- 라이선스를 신경 쓰고 싶지 않다면 처음부터 **OpenJDK 벤더 빌드**(Temurin, Corretto 등)로 시작하는 게
  가장 마찰이 적은 선택이다.

## 정리

- Java **언어** 사용은 항상 무료.
- OpenJDK는 무료 오픈소스 구현체이고, 실제 설치는 벤더의 바이너리 배포판으로 한다.
- Oracle JDK는 NFTC 라이선스(JDK 17~)로 대부분 무료지만, LTS 기간 종료 후 지원이나 Oracle
  제품/서비스 연동 시에는 유료로 전환될 수 있다.
- 라이선스 리스크를 피하려면 애초에 OpenJDK 벤더 빌드를 기본값으로 두는 편이 안전하다.
