### SpringBoot에서의 값 객체란 무엇인가? 

일반적인 RDBMS 데이터베이스는 Primary key , Forien Key 를 통해서 두 데이터(엔터티)간에 관계를 매핑 합니다. 반면 JPA는 @ManyToOne 등 과 같은 어노테이션을 통해서 매핑을 할수 있습니다. JPA 에서는 **값 객체 는 @Id 가 없는 객체를 의미합니다**.

  * 단독으로 조회/수정 삭제 되지 않는 객체
  * 단독 으로 처리된다는 것은 하나의 엔테티라는 의미 입니다.



예시로 상품(엔터티)가 존재 할때 **상품의 이미지를 값 객체로 선언하여 구현** 합니다. 이는 단독으로 조회/수정 삭제 되지 않는 객체 이기 때문입니다.

  * 상품 이지미 관리 - ProductImage.class
  * 상품 관리 - ProductEntity.class


    
    
    @Embeddable
    @Builder
    @AllArgsConstructor
    @NoArgsConstructor
    @Getter
    @ToString
    public class ProductImage implements Comparable<ProductImage>{
        private int idx;
        private String fileName;
    
        @Override
        public int compareTo(ProductImage o){
            return this.idx - o.idx;
        }
    }
    
    
    @Entity
    @Table(name = "tbl_products")
    @Getter
    @ToString(exclude = "images")
    @AllArgsConstructor
    @NoArgsConstructor
    @Builder
    @EntityListeners(value = {AuditingEntityListener.class})
    public class ProductEntity {
        @Id
        @GeneratedValue(strategy = GenerationType.IDENTITY)
        private Long pno;
    
        private String pname;
    
        private int price;
    
        private String content;
    
        private String writer;
    
        @CreatedDate
        private LocalDateTime joinDate;
    
        @LastModifiedDate
        private LocalDateTime modifiedDate;
    
        @ElementCollection(fetch = FetchType.LAZY)
        @CollectionTable(name = "tbl_product_images",joinColumns = @JoinColumn(name = "pno"))
        @Builder.Default
        private SortedSet<ProductImage> images = new TreeSet<>();
    
        public void addImage(String fileName){
            ProductImage productImage = ProductImage.builder().
                    fileName(fileName)
                    .idx(images.size())
                    .build();
        }
    
        public void clearImages(){
            images.clear();
        }
    
        public void changeTitle(String title){
            this.pname  =title;
        }
    
        public void changePrice(int price){
            this.price = price;
        }
    
        public void changeContent(String content){
            this.content = content;
        }
    }

### @Embeddable / @ElementCollection

위 코드 에서 **ProductImage에 집중해서 코드를 보면 @Embeddable라고 선언** 하였습니다. 상품이미지를 값 객체로서 선언한다는 뜻입니다. 그 후 @Entity로 실제 사용중인 **상품엔터티에****@ElementCollection를 적용하여****사용** 하였습니다.

  * 다른 엔터티의 속성값으로 사용되기 위해 만들어진 객체 라는 의미입니다.
  * 해당 클래스는 엔터티가 아니라는 것을 의미합니다.



@ElementCollection은 해당 컬렉션이 값타입 컬렉션임을 표시하는 어노테이션으로 @Entity에서 값객체를 사용할때 이용 합니다.

#### @CollectionTable

컬렉션 데이터가 저장될 테이블의 구체적인 설정을 하고 싶다면 @CollectionTable 어노테이션을 활용하면 됩니다 

#### SortedSet , TreeSet

**SortedSet <Collection>** : SortedSet은 Java의 Set 인터페이스의 서브인터페이스로, 요소들이 항상 정렬된 상태로 유지되는 특성을 가집니다. 즉, SortedSet에 추가된 요소들은 자동으로 정렬됩니다.

  * Comparable 인터페이스를 구현하고 있는 클래스의 객체를 원소로 사용해야합니다. 따라서 ProductImage에 Comparable를 상속받아 compareTo를 Override 하여 구현한 것 입니다.
  * SortedSet 인터페이스의 기본 구현체로 TreeSet 클래스를 제공해주고 있습니다.


    
    
    private SortedSet<ProductImage> images = new TreeSet<>();

구현된 값객체 filed 를 이용하여 순차적으로 이미지를 넣는 함수를 구현 했습니다.
    
    
    public void addImage(String fileName){
           ProductImage productImage = ProductImage.builder().
                   fileName(fileName)
                   .idx(images.size())
                   .build();
       }

###  **지연로딩(Lazy Loading) 전략** \- @EntityGraph

@EntityGraph는 관련된 엔터티나 값 객체 등의 로딩을 조절하기 위해서 사용합니다.

**값타입 컬렉션은 지연로딩(Lazy Loading) 전략을 사용** 합니다.

\- 엔티티가 로딩될 때, 컬렉션의 모든 데이터가 같이 로딩되면 성능저하를 불러올 수 있습니다.

**\- 필요할때 까지 로딩하지 않는 것이 지연로딩 기법입니다.**

  
**주요 특징**

  * 쿼리 최적화: EntityGraph는 특정 엔티티와 그와 연관된 엔티티들을 미리 로딩하도록 정의할 수 있습니다. 이 방식은 복잡한 JOIN이나 다수의 쿼리를 줄여 성능을 최적화하는 데 유용합니다.
  * 명시적인 로딩 전략 지정: JPA에서는 기본적으로 Lazy와 Eager 로딩 전략을 사용합니다. 하지만 EntityGraph를 사용하면 이들 전략을 명시적으로 제어할 수 있습니다. 즉, 기본 로딩 전략 외에도 필요할 때만 연관된 엔티티를 로딩하도록 설정할 수 있습니다.
  * JPQL과 함께 사용: EntityGraph는 JPQL(혹은 Criteria API)과 함께 사용되어 쿼리에서 직접 어떤 엔티티들을 로딩할지 정의할 수 있습니다.
  * attributePaths에 같이 로딩하려는 속성 적용
  * EntityGraph.EntityGraphType.FETCH 를 이용하여 원하는 속성을 같이 로딩.


    
    
    public interface ProductRespository extends JpaRepository<ProductEntity,Long> {
    
        @EntityGraph(attributePaths = {"images"},type = EntityGraph.EntityGraphType.FETCH)
        @Query("select  p from ProductEntity p where p.pno = :pno")
        Optional<ProductEntity> getProduct(@Param("pno") Long pno);
        
    }

### @BatchSize vs fetch 이용

예를 들어 1000개의 상품을 조회 할때 어떻게 조회 할 것인가 ? 기본적으로 Hibernate는 1000개의 상품을 조회한 후,  
각 상품과 연관된 이미지가 있다면 이미지를 조회하기 위해 별도의 쿼리를 실행합니다. 이를 **N+1 문제** 라고 이야기 합니다.  
즉 , **첫 번째 쿼리(1)로 기본 엔티티를 가져온 후, 연관된 엔티티를 가져오기 위해 추가적인 쿼리(N)가 기본 엔티티의 수만큼 발생하는 현상** 을 말합니다.   
  


**해결 1.****Entity에 값 객체를 @BatchSize로 적용 :**  
사용시 상품 조회 후 , 이미지 를 한번에 조회 한다

### 결론  


1.**@BatchSize를 사용할 때**

  * FetchJoin으로 즉시 로딩되지 않는 엔티티들에 대해 BatchSize가 효과적일 수 있음
  * **최상위 엔티티의 개수가 적고, 각 엔티티가 참조하는 하위 엔티티가 많을 때** 효과적입니다.



2\. **FetchJoin을 사용할 때**

  * 연관된 엔티티가 상대적으로 적거나 적절히 필터링된 경우
  * 쿼리에서 연관된 모든 데이터를 즉시 로딩해야 하는 경우에 유용 하다.
  * , 페이징 처리 시 문제가 발생할 수 있습니다   
  
*공부하고 있는 구멍가게 코딩단 저자는 이렇게 말한다. *
