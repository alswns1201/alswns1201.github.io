**Spring Cloud Config + Spring Cloud Bus + RabbitMQ(AMQP)** 조합을 기준으로,

  * 왜 Bus가 필요한지
  * RabbitMQ(AMQP)가 어떤 역할을 하는지
  * 실제로 어떻게 설정하고 동작하는지



를 **개념 → 구조 → 실습 코드** 순서로 정리.

## 1\. Spring Cloud Bus가 왜 필요한가

### 문제 상황

Config Server를 사용하는 마이크로서비스 환경을 가정한다.
    
    
    Config Server
    ├─ order-service
    ├─ member-service
    └─ payment-service

  * 설정 변경 발생 (application.yml 수정)
  * Config Server는 최신 설정을 제공함
  * **각 서비스는****/actuator/refresh****를 직접 호출해야 반영됨**


    
    
    POST /order-service/actuator/refresh
    POST /member-service/actuator/refresh
    POST /payment-service/actuator/refresh

## 2\. Spring Cloud Bus의 핵심 아이디어

> **이벤트를 메시지로 흘려서 모든 서비스에 동기화한다**

  * Config 변경 → 이벤트 발생
  * 메시지 브로커(RabbitMQ, Kafka)를 통해 **브로드캐스트**
  * 모든 서비스가 이벤트를 수신하고 자동 refresh


    
    
    Config Server
    │
    │ (Refresh Event)
    ▼
    RabbitMQ (Exchange)
    │
    ├─ order-service
    ├─ member-service
    └─ payment-service

결과 : POST /actuator/busrefresh (단 한 번) → 전체 서비스 설정 갱신

## 3\. RabbitMQ(AMQP)의 역할

Spring Cloud Bus는 **메시지 브로커가 반드시 필요** 하다.

### AMQP란?

    * Advanced Message Queuing Protocol
    * 메시지 기반 비동기 통신 표준



### RabbitMQ 구조 요약
    
    
    Producer → Exchange → Queue → Consumer

Spring Cloud Bus에서:

  * **Producer** : Config Server
  * **Exchange** : Spring Cloud Bus 전용 Exchange
  * **Queue** : 각 마이크로서비스별 Queue
  * **Consumer** : 각 서비스 인스턴스



👉 서비스 수가 늘어나도 **자동 확장** 됨

## 5\. RabbitMQ 실행 (Docker)
    
    
    docker run -d \
    --name rabbitmq \
    -p 5672:5672 \
    -p 15672:15672 \
    rabbitmq:3-management

  * AMQP 포트: 5672
  * 관리 콘솔: http://localhost:15672
  * 기본 계정: guest / guest



## 6\. Config Server 설정

### 의존성
    
    
    implementation 'org.springframework.cloud:spring-cloud-config-server'
    implementation 'org.springframework.cloud:spring-cloud-starter-bus-amqp'
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
    
    
    server:
    port: 8888
    
    
    spring:
    application:
    name: config-server
    cloud:
    config:
    server:
    git:
    uri: https://github.com/your/config-repo
    rabbitmq:
    host: localhost
    port: 5672
    username: guest
    password: guest
    
    
    management:
    endpoints:
    web:
    exposure:
    include: busrefresh
    
    
    @EnableConfigServer
    @SpringBootApplication
    public class ConfigServerApplication {
    public static void main(String[] args) {
    SpringApplication.run(ConfigServerApplication.class, args);
    }
    }

### 7\. 마이크로서비스 설정 (order-service)
    
    
    implementation 'org.springframework.cloud:spring-cloud-starter-config'
    implementation 'org.springframework.cloud:spring-cloud-starter-bus-amqp'
    implementation 'org.springframework.boot:spring-boot-starter-actuator'
    
    
    spring:
    application:
    name: order-service

    host: localhost

    password: guest
    
    
    management:
    endpoints:
    web:
    exposure:
    include: refresh

## 9\. Bus Refresh 실행

POST http://localhost:8888/actuator/busrefresh

  * RabbitMQ에 이벤트 발행
  * 모든 서비스가 이벤트 수신
  * /actuator/refresh 자동 실행
  * v1 → v2 → 즉시 반영 



## 10\. 핵심 정리

항목설명

Spring Cloud Config | 설정 중앙화  
---|---  
Spring Cloud Bus | 설정 변경 이벤트 브로드캐스트  
RabbitMQ(AMQP) | 이벤트 전달 채널  
busrefresh | 단 한 번의 전체 갱신  
  
> **Spring Cloud Bus + Config Server =  
>  설정 변경 시 “자동 반영”을 위한 운영 방식**

배포랑은 분리된 **운영 자동화 레이어** 다.
