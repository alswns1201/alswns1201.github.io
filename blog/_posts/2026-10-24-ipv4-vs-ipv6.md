클라이언트 IP를 다루다 보면 로그에 `0:0:0:0:0:0:0:1` 같은 값이 찍히거나,
IP를 저장하는 컬럼 길이가 모자라는 일이 생긴다. 둘 다 **IPv6**를 생각하지 않아서 생기는 문제다.
IPv4와 IPv6가 무엇이 다른지, 그리고 백엔드 개발자가 실제로 신경 써야 하는 부분을 정리해 둔다.

> 예시 주소는 문서용으로 예약된 대역(IPv4 `192.0.2.0/24`, `203.0.113.0/24` / IPv6 `2001:db8::/32`)을 썼다.

## 한눈에 보는 차이

| | IPv4 | IPv6 |
|---|---|---|
| 주소 길이 | **32비트** | **128비트** |
| 주소 개수 | 약 43억 개 (2³²) | 약 3.4 × 10³⁸개 (2¹²⁸) |
| 표기 | 10진수 4개, 점으로 구분 `192.0.2.1` | 16진수 8묶음, 콜론으로 구분 `2001:db8::1` |
| 루프백 | `127.0.0.1` | `::1` |
| 사설 주소 | `10/8`, `172.16/12`, `192.168/16` | `fc00::/7` (ULA) |
| 링크 로컬 | `169.254/16` | `fe80::/10` |
| 주소 부족 대응 | **NAT**로 여러 기기가 공인 IP 하나 공유 | 기기마다 공인 주소를 줄 수 있음 |
| 헤더 | 가변 길이(20~60바이트), 체크섬 있음 | **고정 40바이트**, 체크섬 없음, 확장 헤더 |
| 단편화 | 라우터도 쪼갤 수 있음 | **보내는 쪽만** 쪼갬 (라우터는 안 함) |
| 브로드캐스트 | 있음 | **없음** (멀티캐스트로 대체) |
| MAC 주소 찾기 | ARP | NDP (ICMPv6 기반) |
| 주소 자동 설정 | 주로 DHCP | SLAAC(자동) 또는 DHCPv6 |

## 왜 IPv6가 나왔나

IPv4 주소는 약 43억 개다. 인터넷에 붙는 기기가 이보다 훨씬 많아지면서 주소가 모자라게 됐고,
그동안은 **NAT**(공유기 하나가 공인 IP 하나를 받고, 안쪽 기기들은 사설 IP를 쓰는 방식)로 버텨 왔다.

```
[노트북 192.168.0.10] ─┐
[휴대폰 192.168.0.11] ─┼─ [공유기 NAT] ── 공인 IP 203.0.113.7 ── 인터넷
[TV     192.168.0.12] ─┘
```

NAT 덕분에 주소는 아꼈지만, 밖에서 보면 **여러 기기가 같은 IP**로 보이고,
밖에서 안쪽 기기로 먼저 연결하기 어려워지는 등의 부작용이 있다.

IPv6는 주소를 128비트로 늘려서 **기기마다 공인 주소를 줘도 남을 만큼** 만들었다.
주소만 늘린 게 아니라 헤더를 고정 길이로 단순하게 만들어 라우터 처리를 가볍게 했고,
주소 자동 설정(SLAAC)도 기본으로 넣었다.

> IPv6는 IPv4와 **호환되지 않는 별개의 프로토콜**이다. 그래서 한동안은 둘을 같이 쓰는 **듀얼 스택**이 일반적이다.

## IPv6 주소 읽는 법

원래 모양은 16비트(16진수 4자리)씩 8묶음이다.

```
2001:0db8:0000:0000:0000:ff00:0042:8329
```

줄여 쓰는 규칙이 두 가지 있다.

1. **각 묶음의 앞자리 0은 생략**할 수 있다. `0db8` → `db8`, `0042` → `42`, `0000` → `0`
2. **0으로만 된 묶음이 연속되면 `::`로 한 번만** 줄일 수 있다.

```
2001:0db8:0000:0000:0000:ff00:0042:8329
→ 2001:db8:0:0:0:ff00:42:8329      (규칙 1)
→ 2001:db8::ff00:42:8329           (규칙 2)
```

`::`를 두 번 쓰면 각각 몇 묶음인지 알 수 없어서 **한 주소에 한 번만** 쓸 수 있다.
루프백 `::1`은 `0:0:0:0:0:0:0:1`을 줄인 것이다.

### 네트워크 부분과 호스트 부분

IPv6는 보통 **앞 64비트가 네트워크(프리픽스), 뒤 64비트가 기기(인터페이스 ID)**다.

```
2001:db8:1234:5678 : abcd:ef01:2345:6789
└── 네트워크 /64 ──┘  └──── 기기 ─────┘
```

ISP는 가정이나 사용자에게 보통 `/64` 이상(`/56`, `/48` 등)을 통째로 준다.
즉 **한 사용자가 쓸 수 있는 IPv6 주소가 2⁶⁴개 이상**이고, 기기는 개인정보 보호를 위해 주소 뒤쪽을 주기적으로 바꾸기도 한다.
이게 뒤에서 볼 IP별 제한에 영향을 준다.

## 백엔드에서 신경 써야 할 점

### 1) 로컬에서 `0:0:0:0:0:0:0:1`이 찍히는 이유

로컬에서 `http://localhost:8080`으로 요청하면 `request.getRemoteAddr()`가 `127.0.0.1`이 아니라
`0:0:0:0:0:0:0:1`로 나오는 경우가 있다. `localhost`가 IPv6 루프백 `::1`로 연결됐기 때문이고, **정상**이다.

- 자바는 IPv6 주소를 `::` 축약 없이 `0:0:0:0:0:0:0:1`처럼 **풀어서** 문자열로 만든다.
- IPv4로 테스트하고 싶다면 `http://127.0.0.1:8080`으로 요청하거나, JVM 옵션 `-Djava.net.preferIPv4Stack=true`를 준다.
- "로컬 요청이면 허용" 같은 코드를 `"127.0.0.1".equals(ip)`로 짜면 IPv6에서 빠진다.
  문자열 비교 대신 `InetAddress.getByName(ip).isLoopbackAddress()`를 쓴다.

### 2) 같은 주소도 문자열이 여러 개다

IPv6는 줄여 쓰는 방법 때문에 **같은 주소가 여러 문자열**로 표현된다.

```
2001:db8::1
2001:db8:0:0:0:0:0:1
2001:0db8:0000:0000:0000:0000:0000:0001
```

IP를 **Redis 키나 DB 값으로 쓸 때** 문자열 그대로 쓰면 같은 IP가 다른 키로 나뉜다.
한 가지 형식으로 정규화해서 쓴다.

```java
// 자바 표준 라이브러리로 정규화 (항상 같은 형태의 문자열이 나온다)
String normalized = InetAddress.getByName(ip).getHostAddress();
```

> `InetAddress.getByName()`에 IP가 아닌 문자열(도메인)을 넣으면 **DNS 조회**를 한다.
> 요청 헤더처럼 외부에서 온 값을 넣을 때는 먼저 IP 형식인지 검증하거나, Guava의 `InetAddresses.forString()`처럼 DNS 조회를 하지 않는 방법을 쓴다.

### 3) IPv4-mapped IPv6 주소

듀얼 스택 서버에서는 IPv4 클라이언트가 `::ffff:192.0.2.1`처럼 **IPv6 모양으로 감싸진** 주소로 보일 때가 있다.
같은 클라이언트가 `192.0.2.1`과 `::ffff:192.0.2.1` 두 가지로 찍히면 카운트가 갈린다.
위의 `InetAddress.getByName()`은 이런 주소를 `Inet4Address`로 돌려줘서 `192.0.2.1`로 맞춰진다.

### 4) 저장 컬럼 크기

| 저장 방식 | 크기 |
|---|---|
| IPv4만 문자열 | `VARCHAR(15)` (`255.255.255.255`) |
| IPv6까지 문자열 | **`VARCHAR(45)`** (IPv4-mapped 최대 길이 기준) |
| 바이너리 | `VARBINARY(16)` (IPv4는 4바이트, IPv6는 16바이트) |

`VARCHAR(15)`로 만들어 둔 컬럼에 IPv6가 들어오면 잘리거나 저장이 실패한다.
MySQL이라면 `INET6_ATON()`/`INET6_NTOA()`로 바이너리 변환을 할 수 있고, PostgreSQL은 `inet` 타입이 둘 다 지원한다.

### 5) IP별 횟수 제한은 IPv6에서 /64 단위로

IPv4에서는 "IP 하나 = 사용자(또는 공유기) 하나"로 보고 제한을 걸어도 큰 문제가 없었다.
하지만 IPv6에서는 앞에서 본 것처럼 **한 사용자가 /64 안의 주소를 마음대로 바꿔 쓸 수 있다.**
주소 하나 단위로 세면 사실상 제한이 없는 것과 같다.

```
2001:db8:1234:5678::1     ┐
2001:db8:1234:5678::2     ├ 같은 사용자, 다른 주소 → 주소 단위로 세면 각각 1회
2001:db8:1234:5678::abcd  ┘
```

그래서 IPv6는 **앞 64비트(/64)로 묶어서** 세는 게 일반적이다.

```java
public static String rateLimitKey(String ip) throws UnknownHostException {
	InetAddress address = InetAddress.getByName(ip);   // 검증된 IP 문자열이라고 가정
	if (address instanceof Inet4Address) {
		return address.getHostAddress();               // IPv4는 주소 그대로
	}
	byte[] bytes = address.getAddress();               // IPv6 16바이트
	Arrays.fill(bytes, 8, 16, (byte) 0);               // 뒤 64비트를 0으로
	return InetAddress.getByAddress(bytes).getHostAddress() + "/64";
}
```

```
2001:db8:1234:5678::abcd  →  2001:db8:1234:5678:0:0:0:0/64
192.0.2.1                 →  192.0.2.1
```

### 6) URL에 IPv6를 쓸 때는 대괄호

IPv6 주소에는 콜론이 들어 있어서 포트와 구분이 안 된다. URL에서는 **대괄호**로 감싼다.

```
http://192.0.2.1:8080/health
http://[2001:db8::1]:8080/health
```

설정 파일이나 코드에서 `host + ":" + port`로 주소를 조립하면 IPv6에서 깨진다.

### 7) ALB 듀얼 스택

ALB의 IP 주소 유형을 **dualstack**으로 바꾸면 클라이언트가 IPv6로도 접속할 수 있다.
이때 ALB와 서버 사이는 대상 그룹 설정대로(보통 IPv4) 연결되지만,
`X-Forwarded-For`에는 **클라이언트의 IPv6 주소**가 그대로 들어온다.

즉 서버가 IPv6를 안 쓰더라도 **ALB를 듀얼 스택으로 바꾸는 순간 애플리케이션은 IPv6 클라이언트 IP를 받게 된다.**
위의 정규화, 컬럼 크기, /64 제한을 미리 챙겨 둬야 하는 이유다.
`X-Forwarded-For`를 어떻게 읽는지는 [X-Forwarded-For와 getRemoteAddr() 차이](/posts/x-forwarded-for-vs-remote-addr/)에 정리했다.

## 한 줄 정리

> IPv4는 32비트(약 43억 개)라 NAT로 주소를 아껴 쓰고, IPv6는 128비트라 기기마다 공인 주소를 줄 수 있다.
> 백엔드에서는 IPv6 주소를 **정규화**해서 비교·저장하고, 컬럼은 `VARCHAR(45)` 이상으로,
> IP별 제한은 IPv6일 때 **/64 단위**로 묶어서 세야 한다.
