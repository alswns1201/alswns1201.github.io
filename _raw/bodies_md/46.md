실시간 데이터 전송이 필요한 경우(예: 주식 시세, 로그 스트리밍, 실시간 알림 등), Spring에서는 두 가지 방식으로 서버에서 클라이언트로 데이터를 “스트리밍” 형태로 보낼 수 있다.

이번 글에서는 1️⃣ 전통적인 StreamingResponseBody 방식과 2️⃣ Reactive 기반 WebFlux의 Flux 스트리밍  
두 가지를 비교해본다.

* * *

### 1\. StreamingResponseBody — 직접 OutputStream 다루기

먼저 기존의 서블릿 기반(Spring MVC)에서 지원하는 방식이다.
    
    
    @GetMapping("/stream")
        public StreamingResponseBody streamStocks(HttpServletResponse response) {
            response.setContentType("text/event-stream");
            return outputStream -> {
                stockService.getAllStock()
                        .forEach(stock -> {
                            try {
                                String json = new ObjectMapper()
                                        .writeValueAsString(stock) + "\n";
                                outputStream.write(json.getBytes());
                                outputStream.flush();
    
                            } catch (Exception ex) {
                                throw new RuntimeException(ex.getMessage());
                            }
                        });
            };
        }
    
    @GetMapping("/live")
        public StreamingResponseBody streamStockPrices(HttpServletResponse response) {
            response.setContentType("text/event-stream"); // so browser/clients treat it as a stream
    
            return (OutputStream outputStream) -> {
                try {
                    for (int i = 0; i < 20; i++) { // simulate 20 updates
                        double price = 100 + new Random().nextDouble() * 10; // random stock price
                        String update = "Stock Price: " + price + "\n";
    
                        outputStream.write(update.getBytes());
                        outputStream.flush();
    
                        Thread.sleep(1000);
                    }
                } catch (Exception e) {
                    e.printStackTrace();
                }
            };
        }

#### 💡 요약

  * 한 요청당 하나의 스레드가 붙는다.
  * OutputStream을 직접 제어한다.
  * flush 타이밍을 직접 조절해야 한다.
  * 동시 요청이 많으면 스레드 점유가 늘어나 부하가 커진다.



즉, “**명령형 방식으로 내가 직접 데이터를 밀어주는 구조** ”다.

* * *

### 2\. WebFlux — Reactive 스트리밍

이제 같은 동작을 Spring WebFlux를 이용해 구현해보자.
    
    
        @GetMapping(value = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
        public Flux<Stock> streamStocks(){
            return stockService.streamStocks();
        }
    
        @GetMapping(value = "/live", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
        public Flux<String> streamStockPrice(){
            return Flux.interval(Duration.ofSeconds(1))
                    .take(20)
                    .map(i->{
                        double price = 100 + new Random().nextDouble() * 10;
                        return "Stock Price: " + price;
                    });
        }

#### 💡 요약

  * Flux는 Publisher이며, 데이터를 “미리 만들어두지 않고” **흐름 자체를 정의** 한다.
  * MediaType.TEXT_EVENT_STREAM_VALUE를 지정하면 SSE(Server-Sent Events) 형식으로 자동 전송된다.
  * 내부적으로 Netty 등을 사용해 **논블로킹 이벤트 루프 기반** 으로 작동한다.
  * 스레드 점유가 거의 없고, 구독자(Subscriber)가 있을 때만 데이터가 전송된다.



즉, “**선언적으로 데이터 스트림을 흘려보내는 구조** ”다.

* * *

### 3\. 두 방식의 차이 정리

구분StreamingResponseBodyWebFlux (Flux)  실행 모델 | 서블릿 (Blocking I/O) | 논블로킹 (Reactive)  
---|---|---  
스레드 관리 | 요청당 스레드 1개 | 이벤트 루프 기반  
데이터 전송 방식 | 직접 OutputStream 조작 | Flux가 데이터 흐름 관리  
코드 스타일 | 명령형 | 선언형  
동시성 처리 | 스레드 증가에 따라 부하 상승 | 효율적인 리액티브 처리  
사용 예 | 간단한 스트리밍 응답 | 대규모 실시간 서비스, SSE, WebSocket 등  
  
* * *

### 4\. 정리하며

두 방식 모두 “서버에서 클라이언트로 실시간 데이터 전송”을 가능하게 하지만 철학이 다르다.

  * StreamingResponseBody: 내가 직접 밀어준다.
  * Flux: 흐름을 정의하면, 시스템이 알아서 밀어준다.



Spring WebFlux는 코드가 훨씬 깔끔하고 확장성이 좋지만, 프로젝트가 이미 MVC 기반이라면 StreamingResponseBody로도 충분히 구현 가능하다. 결국 선택의 기준은 “규모와 동시성 요구” 다. 규모가 크고 실시간 반응성이 중요하다면 WebFlux로 가는 게 맞다.
