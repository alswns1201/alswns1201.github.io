카프카를 활용한 시스템을 설계하거나 운영할 때 가장 핵심이 되는 것은 데이터가 어떻게 분산 저장되고 장애 상황에서 어떻게 복구되는지에 대한 물리적, 논리적 구조를 파악하는 것입니다.

### 1\. 클러스터와 브로커의 관계

카프카 시스템의 최상위 단위는 클러스터입니다. 클러스터는 여러 대의 브로커로 구성된 분산 시스템을 의미합니다.

  * 브로커: 카프카 서버 한 대를 의미하는 단위입니다.
  * 클러스터링: 여러 대의 브로커가 하나의 군집을 이루어 데이터를 분산 저장하고 관리합니다.
  * 컨트롤러: 클러스터 내 브로커 중 한 대가 컨트롤러 역할을 수행하며 파티션의 리더 선출 및 복제 상태를 관리합니다. 최근에는 KRaft 모드를 통해 외부 의존성 없이 카프카 내부에서 메타데이터를 관리하는 추세입니다.



### 2\. 토픽과 파티션: 데이터 저장의 논리적 단위

토픽은 데이터를 구분하기 위한 논리적인 명칭이며 실제 데이터가 저장되는 물리적인 공간은 파티션입니다.

  * 파티셔닝: 하나의 토픽을 여러 파티션으로 나누어 저장함으로써 단일 서버의 용량 한계를 극복하고 병렬 처리를 가능하게 합니다.
  * 병렬 처리: 파티션은 컨슈머 그룹 내의 컨슈머와 일대일로 매칭될 수 있는 최소 단위입니다. 처리량을 높여야 하는 경우 파티션 수를 늘리고 그에 맞춰 컨슈머를 추가하여 확장성을 확보합니다.
  * 순서 보장: 카프카는 동일 파티션 내에서의 메시지 순서만 보장합니다. 여러 파티션으로 분산된 메시지 간의 순서는 보장되지 않으므로 설계 시 주의가 필요합니다.



### 3\. 레플리카: 데이터 가용성과 복제

레플리카는 파티션의 복사본을 의미하며 가용성 확보를 위한 핵심 개념입니다.

  * 리더와 팔로워: 각 파티션은 하나의 리더와 여러 명의 팔로워로 구성됩니다. 프로듀서와 컨슈머는 오직 리더 파티션하고만 통신합니다.
  * 복제 과정: 팔로워 파티션은 리더 파티션으로부터 데이터를 지속적으로 복제하여 자신의 저장소에 동기화합니다.
  * ISR (In-Sync Replicas): 리더와 동기화가 정상적으로 이루어지고 있는 팔로워들의 그룹입니다. 리더 브로커에 장애가 발생하면 ISR 그룹 내의 팔로워 중 하나가 새로운 리더로 승격됩니다.
  * 복제 계수: 토픽 생성 시 설정하는 레플리카 개수는 브로커 수보다 클 수 없습니다. 예를 들어 브로커가 3대인 클러스터에서 레플리카 계수를 3으로 설정하면 각 서버에 파티션 복제본이 하나씩 위치하게 됩니다.



### 4\. 오프셋과 컨슈머 그룹의 동작

데이터가 파티션에 저장될 때마다 순차적으로 증가하는 숫자를 오프셋이라고 합니다.

  * 오프셋: 파티션 내에서 메시지의 위치를 나타내는 고유 번호입니다.
  * 커밋: 컨슈머가 메시지를 읽고 처리가 완료되었음을 카프카에 알리는 행위입니다. 커밋된 오프셋은 내부 토픽에 저장되어 컨슈머 재시작 시 마지막 지점부터 다시 읽을 수 있게 합니다.
  * 컨슈머 랙: 프로듀서가 적재한 마지막 오프셋과 컨슈머가 마지막으로 커밋한 오프셋 사이의 차이를 의미하며 시스템의 지연 상태를 모니터링하는 지표로 활용됩니다.



### 5\. 실무 설계를 위한 요약

실무 환경에서 안정적인 카프카 운영을 위해서는 다음의 구성을 기본으로 고려해야 합니다.

  1. 가용성: 서버 장애 대응을 위해 최소 3대 이상의 브로커와 레플리카 계수 3 설정을 권장합니다.
  2. 성능: 예상되는 데이터 유입량과 컨슈머 처리 성능을 계산하여 적절한 수의 파티션을 할당합니다.
  3. 안정성: 프로듀서의 전송 성공 보장 범위인 acks 설정과 컨슈머의 오프셋 커밋 시점을 비즈니스 로직에 맞춰 최적화해야 합니다.



결론 

카프카는 클러스터 -> 브로커 -> 토픽 -> 파티션 -> 세그먼트로 구성되어 있다.
