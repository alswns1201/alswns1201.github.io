useQuery

### 선언적인 데이터 페칭과 캐싱: React Query (useQuery)

React 애플리케이션에서 데이터 페칭은 흔한 작업입니다. 하지만 로딩 상태 관리, 에러 처리, 캐싱, 백그라운드 재검증, 재시도 로직 등을 직접 구현하는 것은 반복적이고 복잡할 수 있습니다. React Query는 이러한 데이터 페칭과 관리를 매우 효율적이고 선언적으로 만들어주는 라이브러리입니다. 특히 useQuery 훅은 서버에서 데이터를 비동기적으로 가져오고 관리하는 핵심 도구입니다.

#### useQuery의 주요 특징

  * 자동 캐싱: 데이터를 자동으로 캐시하여, 불필요한 네트워크 요청을 줄이고 성능을 개선합니다. (데이터가 이미 캐시에 있다면 다시 불러오지 않음)
  * 자동 재시도: 네트워크 요청이 실패했을 때 자동으로 재시도 로직을 제공합니다.
  * 백그라운드 데이터 업데이트 (stale-while-revalidate): 사용자에게 캐시된 데이터를 보여주면서 백그라운드에서 최신 데이터를 가져와 UI를 업데이트합니다.
  * 강력한 상태 관리: isLoading, isError, data, error 등 데이터 페칭과 관련된 모든 상태를 선언적으로 제공합니다.
  * 리페칭 (Refetch): 특정 조건(예: 윈도우 포커스 시, 네트워크 재연결 시)에서 데이터를 자동으로 다시 가져오는 등의 기능을 제공합니다.



#### QueryClientProvider 설정

QueryClientProvider는 react-query를 사용하는 React 애플리케이션의 필수적인 설정 및 초기화 단계입니다.

useQuery를 사용하기 전에 React Query의 설정을 제공하기 위해 애플리케이션의 루트 컴포넌트를 QueryClientProvider로 감싸야 합니다.
    
    
    // src/index.js (또는 App.js)
    import React from 'react';
    import ReactDOM from 'react-dom/client';
    import App from './App';
    import { QueryClient, QueryClientProvider } from '@tanstack/react-query'; // React Query 임포트
    
    // 새로운 QueryClient 인스턴스 생성
    const queryClient = new QueryClient();
    
    const root = ReactDOM.createRoot(document.getElementById('root'));
    root.render(
      <React.StrictMode>
        {/* QueryClientProvider로 앱을 감싸줍니다. */}
        <QueryClientProvider client={queryClient}>
          <App />
        </QueryClientProvider>
      </React.StrictMode>
    );

#### useQuery 사용 예시
    
    
    import React from 'react';
    import { useQuery } from '@tanstack/react-query'; // useQuery 임포트
    
    // 데이터를 불러오는 비동기 함수
    const fetchPosts = async () => {
      const response = await fetch('https://jsonplaceholder.typicode.com/posts');
      if (!response.ok) {
        throw new Error('네트워크 응답이 좋지 않습니다.');
      }
      return response.json();
    };
    
    function PostsList() {
      // useQuery 훅 사용
      // 첫 번째 인자: 쿼리 키 (캐싱 및 식별에 사용)
      // 두 번째 인자: 데이터를 불러올 비동기 함수
      const { isLoading, isError, data, error, refetch } = useQuery({
        queryKey: ['posts'],
        queryFn: fetchPosts,
      });
    
      if (isLoading) return <div>게시물을 불러오는 중...</div>;
      if (isError) return <div>오류 발생: {error.message}</div>;
    
      return (
        <div>
          <h1>게시물 목록</h1>
          <button onClick={() => refetch()}>새로고침</button> {/* 수동으로 데이터 다시 불러오기 */}
          <ul>
            {data.map((post) => (
              <li key={post.id}>
                <strong>{post.title}</strong>
                <p>{post.body.substring(0, 100)}...</p>
              </li>
            ))}
          </ul>
        </div>
      );
    }
    
    export default PostsList;

useQuery는 데이터 페칭, 상태 관리, 캐시 처리를 매우 효율적으로 다룰 수 있게 해주어, 복잡한 데이터 동기화 로직을 개발자가 직접 구현할 필요 없이 선언적으로 관리할 수 있도록 돕습니다.

첫번쨰 인자로 queryKey를 받으며 useQuery마다 부여되는 고유 Key 값입니다. 이는 캐싱과도 연결 됩니다. 동일한 키에 대한 값을 조회 했을 경우에 이미 해당 키의 값이 존재하면 서버에 요청하지 않습니다.

### useQuery가 반환하는 값들의 의미

  1. data:
     * 의미: queryFn (여기서는 fetchPosts) 함수가 성공적으로 데이터를 가져왔을 때의 실제 결과 값입니다.
     * 역할: 이 속성이 바로 당신이 서버에서 기대하는 "게시물 목록"과 같은 데이터를 담고 있습니다. 데이터 페칭이 완료되고 에러가 없을 때 이 data 변수에 접근할 수 있습니다.
     * 초기값/에러 시: 데이터가 로딩 중이거나 에러가 발생했을 때는 undefined 또는 이전에 캐시된 값을 가질 수 있습니다.
  2. isLoading (boolean):
     * 의미: 현재 데이터를 불러오는 중인지 여부를 나타내는 불리언 값입니다.
     * 역할: true이면 로딩 스피너를 보여주거나 사용자에게 "데이터를 가져오는 중..." 메시지를 표시하는 등의 UI 처리에 사용됩니다. 데이터 페칭이 시작되면 true였다가, 성공적으로 완료되거나 에러가 발생하면 false가 됩니다.
  3. isError (boolean):
     * 의미: 데이터를 불러오는 중 오류가 발생했는지 여부를 나타내는 불리언 값입니다.
     * 역할: true이면 에러 메시지를 보여주거나 오류 처리 UI를 표시하는 데 사용됩니다.
  4. error (object):
     * 의미: isError가 true일 때, 발생한 오류에 대한 상세 정보를 담고 있는 객체입니다.
     * 역할: 어떤 종류의 에러인지 (네트워크 에러, 서버 응답 에러 등) 정보를 포함하며, 사용자에게 구체적인 에러 메시지를 보여줄 때 활용됩니다.
  5. refetch (function):
     * 의미: 수동으로 데이터를 다시 불러오고 싶을 때 호출하는 함수입니다.
     * 역할: 예를 들어, "새로고침" 버튼을 클릭했을 때 최신 데이터를 다시 서버에서 가져오도록 하고 싶을 때 refetch() 함수를 호출할 수 있습니다.



useQuery에서는 위 내용들을 모두 제공하여 활용할 수 있습니다.
