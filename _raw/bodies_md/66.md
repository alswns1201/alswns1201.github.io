MSA(Microservice Architecture) 환경에서 가장 먼저 마주치는 문제가 있다.

> **“서비스가 많아지면, 서로의 주소를 어떻게 찾을 것인가?”**

이 문제를 해결하기 위해 등장한 것이 **Service Discovery** , 그 대표적인 구현체가 **Spring Cloud Netflix Eureka** 다.

* * *

## 1\. Eureka란 무엇인가

Eureka는 **서비스 등록 및 발견(Service Discovery)** 을 담당하는 컴포넌트다.

구성은 단순하다.

  * **Eureka Server**
    * 서비스 정보를 저장하는 중앙 레지스트리
  * **Eureka Client**
    * 자신을 등록하고, 다른 서비스를 조회하는 주체



즉, **서버는 주소록, 클라이언트는 등록자이자 조회자**

* * *

## 2\. Eureka가 필요한 이유

### 기존 방식의 문제

  * 서비스 간 호출 시 IP/Port를 코드나 설정에 하드코딩
  * 인스턴스가 늘어나거나 포트가 바뀌면 전부 수정 필요
  * 장애 발생 시 유연한 대응 불가



### Eureka 사용 시

  * 서비스는 **이름만으로 통신**
  * 실제 IP/Port는 Eureka가 관리
  * 인스턴스 증감에 자동 대응



* * *

## 3\. Eureka Server 구성

### 3-1. 의존성 추가
    
    
    implementation 'org.springframework.cloud:spring-cloud-starter-netflix-eureka-server'

### 3-2. 애플리케이션 설정
    
    
    @EnableEurekaServer @SpringBootApplication public class EurekaServerApplication { }

### 3-3. application.yml
    
    
    server: 
     port: 8761 
    eureka: 
     client: 
      register-with-eureka: false 
      fetch-registry: false

### 3-4. 실행 결과

  * http://localhost:8761/ 접속
  * Eureka Dashboard 확인 가능



> 이 화면은 **관리 UI** 이며,  
> 실제 클라이언트 통신은 /eureka REST API를 사용한다.

* * *

## 4\. Eureka Client 구성

### 4-1. 의존성
    
    
    implementation 'org.springframework.cloud:spring-cloud-starter-netflix-eureka-client'

### 4-2. application.yml
    
    
    server: 
      port: 8081
    spring: 
       application: 
          name: my-first-service 
          
    eureka: 
       client: 
        register-with-eureka: true 
        fetch-registry: true 
        service-url: 
        defaultZone: http://localhost:8761/eureka/ 
        instance: prefer-ip-address: true

### 핵심 포인트

  * spring.application.name 
    * Eureka에 등록되는 **서비스 ID**
  * defaultZone 
    * 반드시 /eureka 경로여야 함
  * register-with-eureka 
    * 서버에 자신을 등록할지 여부



* * *

## 5\. Eureka Client 동작 흐름

클라이언트 애플리케이션이 기동되면 다음 순서로 동작한다.

  1. 애플리케이션 기동
  2. Eureka Server 주소 확인
  3. 자신의 IP / Port / 상태 정보 전송
  4. Eureka Server에 Instance 등록
  5. 30초 주기로 heartbeat 전송
  6. 서버는 상태를 UP으로 유지



Dashboard에는 다음과 같이 표시된다.

MY-FIRST-SERVICE └── 192.168.0.10:8081 (UP) 

* * *

## 6\. spring.cloud.client.ip-address란?

Eureka Instance ID나 통신 주소에 자주 사용되는 값이다.
    
    
    instance-id: ${spring.cloud.client.ip-address}:${random.value}

### 특징

  * **직접 설정하지 않아도 된다**
  * Spring Cloud가 기동 시 네트워크 인터페이스를 스캔해 자동 계산
  * 로컬, Docker, Kubernetes 환경에 따라 자동 반영



* * *

## 7\. Eureka Server vs Client URL 차이

URL역할  http://localhost:8761/ | 관리 Dashboard  
---|---  
http://localhost:8761/eureka | REST API (Client 통신용)  
  
> **Client의 defaultZone은 반드시 /eureka를 가리켜야 한다.**

* * *

## 8\. @EnableDiscoveryClient에 대한 참고 사항

> **참고**  
>  Spring Cloud 2023.x까지는  
> spring-cloud-starter-netflix-eureka-client 의존성만으로 Discovery Client가 자동 활성화되며,
> 
> Spring Cloud 2025.x 이후 버전에서는  
> @EnableDiscoveryClient를 통해 Discovery 기능을 **명시적으로 활성화해야 하는 경우가 있다.**

  * 과거 버전: **의존성만 있으면 자동 활성화**
  * 최신 버전: **Discovery 기능 opt-in 구조**
  * Eureka는 더 이상 기본 Discovery 전략이 아님

## 9\. 자주 겪는 문제 정리

### 9-1. 서비스가 Dashboard에 안 보일 때

  * Eureka Client 의존성 누락
  * Spring Cloud BOM 미적용
  * 애플리케이션 기동 실패
  * Spring Boot / Cloud 버전 호환 문제



### 9-2. 종료 시 Connection Refused WARN

Request execution failed with message: Connection refused 

  * 애플리케이션 종료 시 등록 해제 요청
  * Eureka Server가 꺼져 있으면 발생
  * **정상적인 종료 시나리오**



* * *

## 10\. Eureka를 언제 쓰는가

### 적합한 경우

  * Spring 기반 MSA 학습
  * Gateway + Service Discovery 구조 이해
  * 레거시 MSA 유지보수



### 부적합한 경우

  * Kubernetes 환경 (K8s 자체 Discovery 사용)
  * 최신 Cloud Native 아키텍처



* * *

## 11\. 정리

  * Eureka는 **서비스 주소 관리 문제를 해결하는 핵심 컴포넌트**
  * Server는 Registry, Client는 등록자
  * Client는 /eureka 엔드포인트로 통신
  * 서비스 이름 기반 통신으로 MSA 확장성 확보



> **Eureka를 이해하면, MSA의 전체 흐름이 보이기 시작한다.**
