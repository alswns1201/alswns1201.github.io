## 

React 개발자라면 한 번쯤은 useEffect 훅 앞에서 고민해 본 경험이 있을 것입니다. 컴포넌트의 생명주기와 사이드 이펙트(Side Effect)를 다루는 강력한 도구인 useEffect는 처음에는 다소 까다롭게 느껴질 수 있습니다.

이 글에서는 useEffect의 기본 개념부터 시작하여, 의존성 배열의 심오한 의미, 그리고 Next.js의 핵심 라우팅 훅인 useRouter와 useSearchParams와의 결합을 통한 실용적인 활용법까지 모든 것을 파헤쳐 보겠습니다.

* * *

### 1. useEffect의 기본 개념: "나는 네가 지난 렌더링에 한 일을 알고 있다"

React는 컴포넌트가 렌더링될 때마다 모든 코드를 다시 실행합니다. 하지만 데이터 가져오기, 구독 설정, DOM 직접 조작, 타이머 설정 등은 렌더링 과정에서 직접적으로 수행하면 안 되는 "사이드 이펙트"입니다. 이러한 작업은 렌더링 결과에 영향을 미치지 않지만, 컴포넌트 외부에 영향을 주거나 외부로부터 데이터를 가져오는 행위이기 때문입니다.

useEffect 훅은 이러한 사이드 이펙트를 React의 렌더링 주기와 동기화하여 안전하게 처리할 수 있도록 돕습니다. 마치 "컴포넌트가 렌더링을 마친 후, 이 작업을 수행해 줘"라고 말하는 것과 같습니다.

**기본 문법:**
    
    
    useEffect(callbackFunction, dependencyArray);

  * **callbackFunction** : useEffect가 수행할 사이드 이펙트 로직이 담긴 함수입니다.
  * **dependencyArray (의존성 배열)**: 이 배열 안에 있는 값들이 **이전 렌더링 시점과 현재 렌더링 시점 사이에 "달라지면" (변하면)** , callbackFunction을 다시 실행합니다.



#### **dependencyArray 의 세 가지 핵심 사용법:**

  1. **의존성 배열이 비어있을 때 ([])**:
     * 컴포넌트가 **처음 마운트될 때 (화면에 나타날 때) 딱 한 번만** callbackFunction을 실행합니다.
     * 컴포넌트가 언마운트될 때 (화면에서 사라질 때) cleanup function이 있다면 실행합니다.
     * **주로 초기 데이터 로딩이나 한 번만 실행되어야 하는 설정에 사용됩니다.**
    
    useEffect(() => {
      console.log('컴포넌트가 마운트될 때 한 번만 실행됩니다.');
      // 초기 데이터 로딩, 이벤트 리스너 등록 등
      return () => {
        console.log('컴포넌트가 언마운트될 때 실행되는 클린업 함수');
        // 이벤트 리스너 해제, 타이머 클리어 등
      };
    }, []); // 빈 배열: 마운트 시 1회 실행, 언마운트 시 클린업

  2. **의존성 배열이 생략될 때 (배열 없음)** :
     * **컴포넌트가 렌더링될 때마다 callbackFunction이 항상 실행됩니다.**
     * **거의 사용하지 않는 패턴입니다.** 무한 루프나 불필요한 연산을 유발할 수 있어 주의해야 합니다.
    
    useEffect(() => {
      console.log('컴포넌트가 렌더링될 때마다 항상 실행됩니다.');
      // 절대 하지 마세요!
    }); // 의존성 배열 없음: 렌더링 시마다 항상 실행

  3. **의존성 배열에 값이 있을 때 ([value1, value2, ...])**:
     * 컴포넌트가 처음 마운트될 때 한 번 실행됩니다.
     * 이후 dependencyArray 안에 있는 value1, value2 등 **어떤 값이라도 이전 렌더링과 비교하여 "달라지면"** callbackFunction을 다시 실행합니다.
     * **가장 일반적이고 유용하게 사용되는 패턴입니다.** 특정 상태나 props의 변화에 반응하는 로직에 사용됩니다.
    
    useEffect(() => {
      console.log(`count 값이 변경되었습니다: ${count}`);
      // count 값에 따라 API 호출, DOM 조작 등
    }, [count]); // count 값이 변할 때마다 실행




#### **클린업 함수 (Cleanup Function):**

useEffect 콜백 함수가 함수를 반환하면, 이 반환된 함수는 "클린업 함수"로 동작합니다.

  * 컴포넌트가 언마운트될 때 실행됩니다.
  * 의존성 배열의 값이 변경되어 useEffect가 다시 실행되기 직전에도, **이전 useEffect의 클린업 함수가 먼저 실행됩니다.**  
이는 메모리 누수를 방지하고 불필요한 사이드 이펙트를 정리하는 데 필수적입니다. (예: setTimeout의 clearTimeout, 이벤트 리스너 제거 등)


    
    
    useEffect(() => {
      const timer = setTimeout(() => {
        console.log('2초 후 실행');
      }, 2000);
    
      return () => { // 클린업 함수
        clearTimeout(timer); // 타이머 정리
        console.log('타이머가 클리어되었습니다.');
      };
    }, []);

### 2\. 라우팅 훅과의 시너지: useRouter & useSearchParams

Next.js는 강력한 파일 기반 라우팅 시스템을 제공하며, 클라이언트 측에서 라우팅과 URL 정보를 다루기 위한 전용 훅들을 제공합니다. 특히 App Router (Next.js 13 이상) 환경에서는 next/navigation 모듈의 훅들이 사용됩니다.

#### **useRouter() 훅:**

  * **역할:** Next.js 애플리케이션의 **라우터 객체** 에 접근할 수 있게 해주는 훅입니다. 이 객체를 통해 프로그래밍 방식으로 페이지를 이동하거나, 현재 라우터의 상태를 읽을 수 있습니다.
  * **주요 기능:**
    * router.push(path): 새로운 경로로 이동 (브라우저 히스토리에 추가).
    * router.replace(path): 현재 경로를 새로운 경로로 교체 (브라우저 히스토리에 현재 페이지를 남기지 않음).
    * router.back(): 이전 페이지로 돌아가기.
    * router.refresh(): 현재 경로를 새로고침 (클라이언트 컴포넌트만 해당).
    * router.pathname (Pages Router): 현재 경로 이름.
    * router.query (Pages Router): URL 쿼리 파라미터 객체. (App Router에서는 주로 useSearchParams를 사용)
  * **예시:**
  * // app/dashboard/page.tsx (클라이언트 컴포넌트)
        'use client';
        import { useRouter } from 'next/navigation';
        
        export default function DashboardPage() {
          const router = useRouter();
        
          return (
            <div>
              <h1>대시보드</h1>
              <button onClick={() => router.push('/settings')}>설정으로 이동</button>
              <button onClick={() => router.replace('/login')}>로그인 페이지로 교체</button>
              <button onClick={() => router.back()}>뒤로 가기</button>
            </div>
          );
        }




#### **useSearchParams() 훅:**

  * **역할:** Next.js 13+ App Router 환경에서 현재 URL의 **쿼리 파라미터 (Query Parameters)** 에 접근할 수 있게 해주는 훅입니다. 이는 Pages Router의 router.query 역할을 대체합니다.
  * **주요 기능:**
    * searchParams.get('key'): 특정 키에 해당하는 쿼리 파라미터의 값을 문자열로 가져옵니다.
    * searchParams.has('key'): 특정 키가 쿼리 파라미터에 존재하는지 확인합니다.
    * searchParams.entries(): 모든 키-값 쌍을 [key, value] 형태로 순회할 수 있는 이터레이터를 반환합니다.
  * **예시:**
  * // app/products/page.tsx?category=electronics&sort=price (클라이언트 컴포넌트)
        'use client';
        import { useSearchParams } from 'next/navigation';
        
        export default function ProductsPage() {
          const searchParams = useSearchParams();
          const category = searchParams.get('category'); // 'electronics'
          const sort = searchParams.get('sort');       // 'price'
        
          return (
            <div>
              <h1>상품 목록</h1>
              <p>카테고리: {category || '전체'}</p>
              <p>정렬 기준: {sort || '기본'}</p>
            </div>
          );
        }

### 3. useEffect와 라우팅 훅의 결합: OAuth 콜백 처리 예시

이제 useEffect, useRouter, useSearchParams가 어떻게 함께 강력한 기능을 구현하는지 살펴보겠습니다. 사용자의 signup/details 페이지에서 소셜 로그인 콜백을 처리하는 시나리오가 대표적인 예시입니다.

**signup/details/page.tsx 코드 예시 (부분 발췌 및 설명):**
    
    
    'use client';
    
    import { Suspense, useEffect, useState } from 'react';
    import { useRouter, useSearchParams } from 'next/navigation';
    
    function SignupDetailsContent() {
      const router = useRouter(); // 라우터 객체 가져오기
      const searchParams = useSearchParams(); // URL 쿼리 파라미터 객체 가져오기
    
      // 카카오 인증 후 URL에 'code' 파라미터가 있는지 감지하고 처리하는 useEffect
      useEffect(() => {
        // 1. URL 쿼리 파라미터에서 'code' 값 추출
        const authorizationCode = searchParams.get('code');
        const storedFormData = localStorage.getItem('signupFormData'); // 이전에 저장된 데이터
        const storedProvider = localStorage.getItem('loginProvider');   // 소셜 제공자 정보
    
        // 'code' 값이 존재하고, 필요한 로컬 스토리지 데이터도 있을 때만 로직 실행
        if (authorizationCode && storedFormData && storedProvider) {
          // 로딩 상태 설정, 에러 초기화 등
          // ...
    
          const formData = JSON.parse(storedFormData);
    
          const completeSignup = async () => {
            try {
              // 2. 백엔드 API 호출: 인가 코드와 폼 데이터를 함께 전송
              const response = await fetch(`/api/auth/login/${storedProvider}`, {
                method: 'POST',
                headers: { 'Content-Type': 'application/json' },
                body: JSON.stringify({
                  authorizationCode, // <-- 카카오가 넘겨준 인가 코드
                  ...formData      // <-- 사용자가 입력한 추가 정보
                }),
              });
    
              if (!response.ok) {
                // ... 에러 처리 ...
              }
    
              const result = await response.json();
              // 3. 로그인 성공 후 JWT 저장, 로컬 스토리지 정리
              localStorage.removeItem('signupFormData');
              localStorage.removeItem('loginProvider');
    
              alert('회원가입 및 로그인이 완료되었습니다!');
              router.push('/'); // 4. 메인 페이지로 이동 (useRouter 사용)
    
            } catch (err) {
              // ... 에러 처리 ...
            } finally {
              // ... 로딩 상태 해제 ...
            }
          };
    
          completeSignup(); // 비동기 함수 실행
        }
      }, [searchParams, router]); // <-- 핵심 의존성 배열
    
      // ... 나머지 폼 렌더링 및 UI 로직 ...
    }
    
    export default function SignupDetailsPage() {
      return (
        <Suspense fallback={<div>Loading...</div>}>
          <SignupDetailsContent />
        </Suspense>
      );
    }

#### **[searchParams, router] 의존성 배열에 대한 심화 이해:**

  1. **searchParams 가 의존성에 있는 이유 (핵심 트리거):**
     * 카카오 인증을 거쳐 redirect_uri (/signup/details)로 돌아올 때, URL에는 ?code=YOUR_AUTH_CODE와 같은 새로운 쿼리 파라미터가 추가됩니다.
     * useSearchParams() 훅은 **URL 쿼리 파라미터가 변경될 때마다 새로운 searchParams 객체 인스턴스를 반환합니다.**
     * JavaScript에서 객체는 **참조(Reference)로 비교** 됩니다. 새로운 searchParams 객체는 이전 객체와 다른 메모리 주소를 가지므로, useEffect는 이 searchParams의 **"참조가 달라졌다"**고 감지합니다.
     * 이 참조 변경이 감지되면, useEffect의 콜백 함수가 다시 실행되고, 그 안에서 searchParams.get('code')를 통해 변경된 URL에서 인가 코드를 정확히 읽어 올 수 있게 됩니다. 이것이 이 useEffect가 콜백을 처리하는 주된 메커니즘입니다.
  2. **router 가 의존성에 있는 이유 (관례 및 견고성):**
     * useEffect 내부에서 router.push('/')와 같은 router 객체의 메서드를 사용하고 있습니다.
     * React의 ESLint 규칙(exhaustive-deps)은 useEffect 콜백 함수 내에서 사용되는 모든 외부 변수를 의존성 배열에 포함하도록 요구합니다. 이는 불필요한 재실행을 막거나, 필요한 재실행이 누락되는 잠재적 버그를 방지하기 위함입니다.
     * **router 객체 자체의 참조는 Next.js 애플리케이션의 생명주기 동안 대부분 변하지 않습니다.** 따라서 router가 의존성 배열에 있다고 해서 searchParams 없이 router만 변해서 useEffect가 자주 실행되는 일은 거의 없습니다. 하지만 ESLint 경고를 피하고 코드의 견고성을 높이기 위한 표준 관례로 포함됩니다.



#### **의존성 배열 요소의 순서: 중요하지 않음**

[searchParams, router]이든 [router, searchParams]이든 **의존성 배열 내 요소들의 순서는 useEffect의 동작에 아무런 영향을 미치지 않습니다.** useEffect는 배열 내의 각 요소를 개별적으로 검사하여 변화 여부만 판단합니다.

* * *

### 결론

useEffect는 React 컴포넌트에서 사이드 이펙트를 안전하고 효율적으로 관리하는 핵심 훅입니다. 의존성 배열을 통해 실행 시점을 세밀하게 제어할 수 있으며, Next.js의 useRouter와 useSearchParams와 같은 라우팅 훅들과 결합하여 복잡한 인증 흐름이나 URL 기반 로직을 매끄럽게 구현할 수 있습니다. 특히 useSearchParams가 URL 쿼리 변경 시 새로운 객체 참조를 반환하는 특성을 이해하는 것이 useEffect와 라우팅 훅을 함께 사용하는 데 있어 가장 중요합니다. 이러한 이해를 바탕으로 더욱 견고하고 효율적인 React/Next.js 애플리케이션을 구축하시길 바랍니다!
