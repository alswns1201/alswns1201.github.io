### 컴포넌트 트리를 가로지르는 데이터: useContext

React의 props 시스템은 데이터를 상위 컴포넌트에서 하위 컴포넌트로 전달하는 데 매우 효과적입니다. 하지만 컴포넌트 중첩이 깊어지면 props drilling (props를 여러 단계의 컴포넌트로 전달해야 하는 현상)이 발생하여 코드가 복잡해지고 유지보수가 어려워집니다. 이때 Context API와 useContext 훅이 해결책으로 등장합니다. 컨텍스트(Context)는 여러 컴포넌트에서 데이터를 전역적으로 공유하고 싶을 때 사용하는 방법입니다. 주로 테마 설정, 로그인 사용자 정보, 언어 설정 등 애플리케이션 전반에 걸쳐 필요한 데이터를 관리하는 데 사용됩니다.

우선, createContext 를 이용해서 Context 객체를 생성합니다. 여기에 기본값을 전달할 수 있습니다.
    
    
    // src/context/MyContext.js
    import { createContext } from 'react';
    
    export const MyContext = createContext('default value'); // 기본값 설정

Context.Provider를 이용하여 Context를 사용할 컴포넌트 트리를 감싸고 value prop을 통해 공유할 데이터를 전달합니다. Provider 아래에 있는 모든 자식 컴포넌트는 해당 Context의 value에 접근할 수 있습니다.
    
    
    // src/App.js (또는 Context를 제공할 상위 컴포넌트)
    import React from 'react';
    import { MyContext } from './context/MyContext';
    import Child from './components/Child'; // 하위 컴포넌트
    
    function App() {
      const value = 'Hello from Context';
    
      return (
        <MyContext.Provider value={value}>
          <Child />
        </MyContext.Provider>
      );
    }
    
    export default App;

useContext: Context의 value를 읽어오는 훅입니다. Context를 사용하려는 함수형 컴포넌트 내에서 호출합니다.
    
    
    // src/components/Child.js (Context를 사용할 하위 컴포넌트)
    import React, { useContext } from 'react';
    import { MyContext } from '../context/MyContext';
    
    function Child() {
      const contextValue = useContext(MyContext); // MyContext의 현재 value를 가져옴
    
      return <div>MyContext에서 받은 값: {contextValue}</div>;
    }
    
    export default Child;

useContext는 props drilling을 해소하여 코드의 가독성과 유지보수성을 크게 향상시킵니다. 하지만 Provider의 value가 변경되면, 해당 Provider의 모든 하위 컴포넌트(심지어 Context 값을 사용하지 않는 컴포넌트도)가 리렌더링될 수 있으므로 주의해야 합니다.

props drilling이란?

필요한 데이터(상태, 함수)를 깊은 자식 컴포넌트에 전달하기 위해 중간 컴포넌트들까지 계속 props로 넘기는 패턴을 Props Drilling이라고 합니다.

### UseMemo

불필요한 재계산 및 불필요한 리렌더링 방지를 위해서 사용합니다. useMemo는 다음과 같은 상황에서 유용합니다.

  1. 고비용(Expensive) 연산 결과 캐싱: 어떤 값을 계산하는 데 많은 시간이나 자원이 소요될 때, 이 값을 useMemo로 감싸서 의존성이 변경되지 않는 한 다시 계산하지 않도록 할 수 있습니다.
  2. 참조 동일성(Referential Equality) 유지: 객체나 배열, 또는 함수(이 경우 useCallback이 더 적합)와 같은 참조 타입의 값이 매 렌더링마다 새롭게 생성되는 것을 방지하여, 하위 컴포넌트의 불필요한 리렌더링을 막을 때 사용합니다. 이것이 바로 질문 주신 contextValue 예시에서 useMemo를 사용하는 핵심 이유입니다.


    
    
    const contextValue = useMemo(() => ({
        message,
        count,
        theme,
        incrementCount,
        toggleTheme,
      }), [message, count, theme, incrementCount, toggleTheme]);

만약 ___useMemo 없이 contextValue_ _를 다음과 같이 사용한다면_ , 자바스크립트에서 객체는 참조(reference)로 비교됩니다. 즉, 비록 객체 안의 message, count 등의 값들이 이전 렌더링과 동일하다고 하더라도,___새로운 객체가 생성되면 메모리상의 주소가 달라지므로 React는 이를 다른 값 으로 인식합니다_. useMemo가 없으면 contextValue 객체의 참조가 매번 바뀌기 때문에, Provider는 value가 매번 "변경되었다"고 판단하여,  _Context를 사용하는 모든 _ _Child , AnotherChild 등의 컴포넌트들을 불필요하게 재렌더링하게 됩니다. 이는 성능 저하의 주요 원인이 됩니다._

#### useMemo와 Context와 같은 전역 변수를 잘 사용하면 일어나는 일?

MyContext.Provider를 감싸는 상위 컴포넌트(예: App.js 또는 특정 데이터 관리 훅을 포함하는 컴포넌트)에서 useState나 useReducer를 사용하여 실시간으로 변하는 데이터를 관리 합니다.

**관심사 분리 와 전역 상태 를 관리하게 됩니다. 즉 데이터 소스가 한 곳에서 관리되고 이를 통해서 여러 컴포넌트가 최신 상태의 값을 공유하게 됩니다.

###  경량 전역 상태 관리 라이브러리: Zustand

Context API는 편리하지만, value 변경 시 불필요한 리렌더링이 발생할 수 있고, 비동기 로직이나 복잡한 상태 트랜지션을 관리하기에는 제한적일 수 있습니다. 이러한 한계를 보완하고, Redux와 같은 대규모 라이브러리보다 더 가볍고 직관적인 대안을 찾는 개발자들에게 Zustand는 훌륭한 선택지입니다. Zustand는 React에서 상태 관리에 관한 여러 개념 중, 특히 러닝 커브가 낮은 경량 상태 관리 라이브러리입니다.

####  Zustand의 장점

직관적인 API로 빠르게 학습하고 적용할 수 있습니다. Provider 불필요 하여 Context API나 Redux와 달리, 애플리케이션을 Provider로 감싸줄 필요가 없어 설정이 간편합니다. 어디서든 useStore 훅을 호출하여 상태에 접근할 수 있습니다.

최적화된 리렌더링으로 필요한 상태가 변화하는 경우에만 해당 상태를 사용하는 컴포넌트가 리렌더링됩니다.
    
    
    npm install zustand

스토어 생성 (useStore.js): create 함수를 사용하여 스토어를 정의합니다.
    
    
    // src/hooks/store/useStore.js
    import { create } from "zustand";
    
    export const useStore = create((set, get) => ({
        // 상태 변수 정의
        user: { name: '', email: '' },
        cartItems: [],
        count: 0,
    
        // 액션 정의 (상태를 변경하는 함수)
        actions: {
            // 사용자 정보 설정 액션
            setUserInfo: (param) => set(state => ({
                user: { ...state.user, name: param.name, email: param.email }
            })),
            // 장바구니에 아이템 추가 액션
            addCartItem: (item) => set(state => ({
                cartItems: [...state.cartItems, item]
            })),
            // 카운트 증가 액션
            incrementCount: () => set(state => ({ count: state.count + 1 }))
        }
    }));

컴포넌트 내에서 useStore 훅을 사용하여 필요한 상태와 액션을 선택적으로 가져와 사용합니다.
    
    
    import React from 'react';
    import { useStore } from "../../hooks/store/useStore"; // 스토어 임포트
    
    function UserProfile() {
        // 특정 액션만 가져와 사용
        const { setUserInfo, incrementCount } = useStore(state => state.actions);
    
        // 특정 상태만 가져와 사용 (선택자 함수로 필요한 부분만 구독하여 불필요한 리렌더링 방지)
        const userName = useStore(state => state.user.name);
        const userEmail = useStore(state => state.user.email);
        const currentCount = useStore(state => state.count);
        const cartItemCount = useStore(state => state.cartItems.length);
    
    
        const handleLogin = () => {
            setUserInfo({ name: '김철수', email: 'chulsoo@example.com' });
            incrementCount();
        };
    
        return (
            <div>
                <h2>사용자 프로필</h2>
                {userName ? (
                    <>
                        <p>이름: {userName}</p>
                        <p>이메일: {userEmail}</p>
                        <p>현재 카운트: {currentCount}</p>
                        <p>장바구니 아이템 수: {cartItemCount}</p>
                        <button onClick={incrementCount}>카운트 증가</button>
                    </>
                ) : (
                    <button onClick={handleLogin}>로그인</button>
                )}
            </div>
        );
    }
    
    export default UserProfile;

Zustand는 간결함과 강력한 성능을 동시에 제공하여, 복잡한 전역 상태 관리 요구사항이 있는 프로젝트에서 Context API의 대안으로 매우 유용합니다.
