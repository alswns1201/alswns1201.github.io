웹 애플리케이션을 개발하다 보면, 요청(Request)에 대한 공통 로그를 남기는 일이 필수적이다. IP, 헤더, URI, 파라미터 등 요청 정보를 체계적으로 기록하면 디버깅, 모니터링, 감사 로그 등 다양한 목적에 활용할 수 있다. 그런데 Spring에서는 **Filter** 와 **AOP** 두 가지 방식으로 접근할 수 있는데, 어떤 상황에 어떤 방식을 쓰는 것이 좋을까?

* * *

### 1️⃣ 요구사항 정의

실무에서 흔히 받는 요구사항을 예로 들어보자.

> Request 로그 포맷:  
> Request: Remote IP: {}, Headers: {}, Method: {}, URI: {}, Parameter: {}
> 
>   * Headers와 Parameter는 JSON 형태로 남긴다.
>   * API가 추가되더라도 로그 처리 코드 변경은 최소화해야 한다.
> 


이 요구사항을 보면 핵심 포인트가 있다.

  1. 요청 단위(Request 단위)로 로그를 남겨야 한다.
  2. 모든 API에 대해 공통으로 적용되어야 한다.
  3. JSON 형태로 Header와 Parameter를 기록해야 한다.
  4. 유지보수가 쉬워야 한다.



* * *

### 2️⃣ Filter로 처리하는 경우

Filter는 서블릿 요청/응답 사이클의 **최초 진입점** 과 **종료 시점** 을 제어할 수 있는 구조다.

**장점**

  * 모든 요청에 대해 일괄 적용 가능 → API 추가/삭제와 무관
  * HTTP 요청의 IP, Method, URI, Header, Parameter에 쉽게 접근 가능
  * 요청 전후 시간을 측정하거나, traceId 생성 같은 공통 처리에 자연스럽게 활용 가능



**단점**

  * Spring Bean 내부 메서드 단위 로직까지는 로그로 잡기 어려움
  * 요청 Body를 읽을 때 InputStream을 Wrapping해야 하는 등 약간 번거로움



**적합한 상황**

  * 요청 단위 접근 로그, 인증/권한 체크, 공통 트래픽 모니터링


    
    
    import com.fasterxml.jackson.databind.ObjectMapper;
    import jakarta.servlet.Filter;
    import jakarta.servlet.FilterChain;
    import jakarta.servlet.ServletException;
    import jakarta.servlet.ServletRequest;
    import jakarta.servlet.ServletResponse;
    import jakarta.servlet.http.HttpServletRequest;
    import org.slf4j.Logger;
    import org.slf4j.LoggerFactory;
    import org.springframework.stereotype.Component;
    
    import java.io.IOException;
    import java.util.Collections;
    
    @Component
    public class RequestLoggingFilter implements Filter {
    
        private static final Logger logger = LoggerFactory.getLogger(RequestLoggingFilter.class);
        private final ObjectMapper objectMapper = new ObjectMapper();
    
        @Override
        public void doFilter(ServletRequest request, ServletResponse response, FilterChain chain) throws IOException, ServletException {
            if (request instanceof HttpServletRequest httpRequest) {
                String ip = request.getRemoteAddr();
                String method = httpRequest.getMethod();
                String uri = httpRequest.getRequestURI();
                String headers = objectMapper.writeValueAsString(Collections.list(httpRequest.getHeaderNames())
                        .stream()
                        .collect(java.util.stream.Collectors.toMap(h -> h, httpRequest::getHeader)));
                String parameters = objectMapper.writeValueAsString(httpRequest.getParameterMap());
    
                logger.info("Request: Remote IP: {}, Headers: {}, Method: {}, URI: {}, Parameter: {}", 
                        ip, headers, method, uri, parameters);
            }
    
            chain.doFilter(request, response);
        }
    }

✅ 특징

  * 모든 요청에 대해 자동 적용
  * Header/Parameter를 JSON으로 직렬화
  * IP, Method, URI 포함

### 3️⃣ AOP로 처리하는 경우

AOP는 Spring Bean의 메서드 호출 시점에 로직을 삽입할 수 있는 구조다.

**장점**

  * 특정 서비스 메서드, 트랜잭션, 예외 발생 지점 등 세밀한 비즈니스 로직 로깅 가능
  * 메서드 인자와 리턴값을 함께 기록 가능
  * 특정 어노테이션 기반으로 선택적 적용 가능



**단점**

  * HTTP 요청 전체를 포괄적으로 잡기는 어렵다
  * Header, IP 등 요청 단위 정보는 RequestContextHolder를 통해 가져와야 하고, 일부 요청은 누락될 수 있음
  * API가 늘어날 때 포인트컷 설정을 신경 써야 함



**적합한 상황**

  * 핵심 비즈니스 로직 실행 흐름 추적
  * 서비스 내부 메서드 실행 시간 측정, 예외 로그 기록


    
    
    import com.fasterxml.jackson.databind.ObjectMapper;
    import jakarta.servlet.http.HttpServletRequest;
    import org.aspectj.lang.JoinPoint;
    import org.aspectj.lang.annotation.Aspect;
    import org.aspectj.lang.annotation.Before;
    import org.slf4j.Logger;
    import org.slf4j.LoggerFactory;
    import org.springframework.stereotype.Component;
    import org.springframework.web.context.request.RequestContextHolder;
    import org.springframework.web.context.request.ServletRequestAttributes;
    
    import java.util.Collections;
    
    @Aspect
    @Component
    public class RequestLoggingAspect {
    
        private static final Logger logger = LoggerFactory.getLogger(RequestLoggingAspect.class);
        private final ObjectMapper objectMapper = new ObjectMapper();
    
        @Before("within(@org.springframework.web.bind.annotation.RestController *)")
        public void logBeforeController(JoinPoint joinPoint) throws Exception {
            ServletRequestAttributes attrs = (ServletRequestAttributes) RequestContextHolder.getRequestAttributes();
            if (attrs != null) {
                HttpServletRequest request = attrs.getRequest();
                String ip = request.getRemoteAddr();
                String method = request.getMethod();
                String uri = request.getRequestURI();
                String headers = objectMapper.writeValueAsString(Collections.list(request.getHeaderNames())
                        .stream()
                        .collect(java.util.stream.Collectors.toMap(h -> h, request::getHeader)));
                String parameters = objectMapper.writeValueAsString(request.getParameterMap());
    
                logger.info("Request: Remote IP: {}, Headers: {}, Method: {}, URI: {}, Parameter: {}", 
                        ip, headers, method, uri, parameters);
            }
        }
    }

✅ 특징

  * Controller 메서드 진입 시점에만 로그
  * Header/Parameter JSON 처리 가능
  * AOP 포인트컷(@RestController)으로 원하는 범위만 선택 가능

### 4️⃣ 결론: 요청 단위 로그라면 Filter가 정석

주어진 요구사항처럼 **모든 요청에 대해 IP, Method, URI, Header, Parameter를 JSON으로 기록** 해야 한다면, Filter가 가장 자연스러운 선택이다.

  * API가 늘어나더라도 Filter 한 곳만 적용하면 되므로 유지보수 부담이 최소화된다.
  * AOP는 서비스 로직 단위 로그나 성능 측정에는 유리하지만, 요청 단위 공통 로그 요구사항에는 적합하지 않다.



즉, 실무에서는 두 가지를 함께 쓰는 경우가 많다.

  * **Filter** → 요청 단위 공통 로그, traceId, 인증 정보
  * **AOP** → 서비스/메서드 단위 로직, 성능 모니터링, 예외 로그



* * *

### 5️⃣ 실무 팁

  1. Header와 Parameter는 Map으로 뽑아 JSON 직렬화해서 기록
  2. 로그 레벨은 INFO 또는 DEBUG로 구분해서 남기고, 민감정보는 마스킹
  3. 요청 처리 시간도 함께 기록하면 성능 모니터링에 유용
  4. Filter와 AOP를 혼용하면 **요청 단위 + 서비스 단위** 로그 모두 확보 가능
