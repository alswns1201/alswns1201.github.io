웹 페이지는 단순히 정보를 보여주는 것을 넘어, 사용자의 상호작용과 데이터를 기억해야 하는 경우가 많습니다. 사용자가 로그인 정보를 다시 입력하지 않거나, 장바구니에 담은 상품이 브라우저를 닫아도 유지되는 것처럼 말이죠. 이러한 "기억력"을 가능하게 하는 것이 바로 HTML5에 도입된 **웹 저장소(Web Storage) API** 의 localStorage와 sessionStorage입니다.

이 글에서는 이 두 가지 강력한 클라이언트 측 저장소에 대해 자세히 알아보고, 어떤 상황에 적합한지, 그리고 어떻게 안전하게 활용할 수 있는지 살펴보겠습니다.

* * *

### 1\. 웹 저장소(Web Storage) API란?

웹 저장소 API는 웹 브라우저 내부에 데이터를 저장할 수 있는 표준화된 방법을 제공합니다. 기존에 쿠키(Cookie)가 유사한 역할을 했지만, 웹 저장소는 다음과 같은 큰 장점을 가집니다:

  * **더 큰 저장 용량:** 일반적으로 5MB ~ 10MB 정도의 데이터를 저장할 수 있어, 4KB 제한이 있는 쿠키보다 훨씬 많은 정보를 담을 수 있습니다.
  * **서버 전송 없음:** 저장된 데이터가 HTTP 요청 시마다 서버로 자동으로 전송되지 않습니다. 이는 네트워크 트래픽을 줄이고 보안을 강화하는 데 도움이 됩니다. (쿠키는 매 요청마다 서버로 전송됩니다.)
  * **간단한 API:** setItem, getItem, removeItem 등 직관적인 메서드로 쉽게 데이터를 다룰 수 있습니다.
  * **키-값(Key-Value) 쌍:** 모든 데이터는 문자열 형태의 키와 값으로 저장됩니다.



웹 저장소 API는 크게 localStorage와 sessionStorage 두 가지 객체를 제공합니다.

* * *

### 2. localStorage: 영원히 기억하는 웹 스토리지

localStorage는 **브라우저 세션과 무관하게 데이터를 영구적으로 저장** 합니다. 즉, 사용자가 브라우저를 닫았다가 다시 열어도, 컴퓨터를 재부팅해도, 데이터는 계속 유지됩니다. 마치 웹사이트가 사용자의 컴퓨터에 데이터를 "영구 보관"하는 것과 같습니다.

#### **주요 특징:**

  * **지속성(Persistence):** 데이터가 명시적으로 삭제되거나 브라우저 캐시가 지워지기 전까지는 계속 유지됩니다.
  * **범위(Scope):** 동일한 도메인(origin, 즉 프로토콜, 호스트, 포트가 동일한) 내에서만 접근 가능합니다. 다른 탭이나 창에서도 동일한 localStorage 데이터에 접근할 수 있습니다.
  * **저장 용량:** 일반적으로 5MB~10MB.
  * **데이터 형식:** 모든 데이터는 **문자열(string)**로 저장됩니다. 객체나 배열을 저장하려면 JSON.stringify()를 사용하여 문자열로 변환해야 하며, 가져올 때는 JSON.parse()로 다시 객체로 변환해야 합니다.



#### **언제 사용해야 할까요?**

  * **사용자 환경 설정:** 다크 모드 설정, 테마 색상, 언어 설정 등 사용자가 한 번 설정하면 계속 유지되어야 하는 정보.
  * **자동 로그인 토큰 (주의 필요):** JWT와 같은 인증 토큰을 저장할 수 있지만, XSS(Cross-Site Scripting) 공격에 취약할 수 있으므로 **HttpOnly 쿠키** 등 더 안전한 방법을 함께 고려해야 합니다.
  * **장바구니 정보:** 비로그인 사용자도 브라우저를 닫았다가 다시 열었을 때 장바구니 내용이 유지되도록 할 때.
  * **임시 데이터 캐싱:** 서버에서 자주 변경되지 않는 데이터를 캐싱하여 로딩 속도를 향상시킬 때.



#### **사용 예시 (JavaScript):**
    
    
    // 1. 데이터 저장 (setItem)
    // 문자열 저장
    localStorage.setItem('username', 'developer_kim');
    console.log('이름 저장됨:', localStorage.getItem('username')); // developer_kim
    
    // 객체 저장 (JSON.stringify 사용)
    const userSettings = {
      theme: 'dark',
      notifications: true
    };
    localStorage.setItem('settings', JSON.stringify(userSettings));
    
    // 2. 데이터 가져오기 (getItem)
    const storedName = localStorage.getItem('username');
    console.log('저장된 이름:', storedName); // developer_kim
    
    const retrievedSettingsString = localStorage.getItem('settings');
    if (retrievedSettingsString) {
      const retrievedSettings = JSON.parse(retrievedSettingsString); // JSON.parse 사용
      console.log('저장된 설정:', retrievedSettings.theme, retrievedSettings.notifications); // dark true
    }
    
    // 3. 특정 데이터 삭제 (removeItem)
    localStorage.removeItem('username');
    console.log('이름 삭제 후:', localStorage.getItem('username')); // null
    
    // 4. 모든 데이터 삭제 (clear)
    localStorage.clear();
    console.log('모든 데이터 삭제 후 설정:', localStorage.getItem('settings')); // null

### 3. sessionStorage: 세션 동안만 기억하는 웹 스토리지

sessionStorage는 localStorage와 거의 동일한 API를 제공하지만, **데이터의 지속성 측면에서 큰 차이** 가 있습니다. sessionStorage에 저장된 데이터는 **현재 브라우저 세션(즉, 해당 탭 또는 창이 열려있는 동안) 동안만 유지** 됩니다. 사용자가 탭이나 창을 닫으면 데이터는 자동으로 삭제됩니다.

#### **주요 특징:**

  * **세션 지속성(Session Persistence):** 데이터가 현재 브라우저 탭/창이 닫히면 사라집니다. 브라우저를 강제 종료하거나 컴퓨터를 재부팅해도 사라집니다.
  * **탭/창 분리:** 동일한 도메인이라도 **다른 탭이나 창에서는 sessionStorage 데이터에 접근할 수 없습니다.** 각 탭/창은 독립적인 sessionStorage를 가집니다.
  * **저장 용량:** localStorage와 유사하게 5MB~10MB.
  * **데이터 형식:** 마찬가지로 **문자열(string)**로 저장됩니다.



#### **언제 사용해야 할까요?**

  * **일회성 폼 데이터:** 다단계 폼에서 사용자가 다음 단계로 넘어갈 때, 현재 단계의 입력값을 임시로 저장하여 페이지 새로고침에도 데이터가 유지되도록 할 때. (단, 탭을 닫으면 데이터가 사라지는 것이 적합할 때)
  * **세션별 검색 필터:** 특정 검색 결과 페이지에서 사용자가 적용한 필터 조건을 해당 세션 동안만 유지하고 싶을 때.
  * **클라이언트 측 라우팅 간 데이터 전달:** SPA(Single Page Application)에서 컴포넌트 간에 데이터를 전달해야 하는데, URL 쿼리나 상태 관리 라이브러리를 사용하기 애매하고 세션 동안만 유지되면 될 때.



#### **사용 예시 (JavaScript):**

localStorage와 동일한 API를 사용합니다.
    
    
    // 1. 데이터 저장 (setItem)
    sessionStorage.setItem('currentStep', '2');
    console.log('현재 단계 저장됨:', sessionStorage.getItem('currentStep')); // 2
    
    // 객체 저장 (JSON.stringify 사용)
    const tempOrder = {
      item: 'Laptop',
      quantity: 1
    };
    sessionStorage.setItem('tempOrder', JSON.stringify(tempOrder));
    
    // 2. 데이터 가져오기 (getItem)
    const storedStep = sessionStorage.getItem('currentStep');
    console.log('저장된 단계:', storedStep); // 2
    
    // 3. 특정 데이터 삭제 (removeItem)
    sessionStorage.removeItem('currentStep');
    
    // 4. 모든 데이터 삭제 (clear)
    sessionStorage.clear();

### 4. localStorage vs sessionStorage vs Cookies

특징 | localStorage | sessionStorage | Cookies  
---|---|---|---  
**지속성** | 영구적 (명시적 삭제 또는 캐시 삭제 전까지) | 현재 탭/창 세션 동안만 유지 | 만료 기간 설정 (서버/클라이언트)  
**접근 범위** | 동일 Origin 내 모든 탭/창 | 동일 Origin 내 현재 탭/창만 | 동일 Origin (경로 설정 가능)  
**용량** | 약 5MB ~ 10MB | 약 5MB ~ 10MB | 약 4KB  
**서버 전송** | X (클라이언트에서만 접근) | X (클라이언트에서만 접근) | O (HTTP 요청마다 자동 전송)  
**API** | JavaScript API만 | JavaScript API만 | JavaScript + HTTP Header  
**보안 취약점** | XSS 공격에 취약 (JS 접근 가능) | XSS 공격에 취약 (JS 접근 가능) | XSS, CSRF (HttpOnly, SameSite 보호)  
  
**선택 가이드:**

  * **localStorage** : 브라우저를 닫아도 정보가 유지되어야 하는 "영구적인" 클라이언트 측 데이터에 사용하세요. (예: 사용자 설정)
  * **sessionStorage** : 사용자가 현재 탭/창에서 특정 작업을 진행하는 동안만 필요한 "임시적인" 데이터에 사용하세요. (예: 다단계 폼의 중간 데이터)
  * **Cookies** : 서버와 클라이언트 간에 자동으로 주고받아야 하는 정보(주로 세션 ID 또는 인증 토큰)에 사용하세요. 특히 HttpOnly 옵션을 사용하여 XSS 공격으로부터 보호할 수 있는 인증 토큰에 주로 활용됩니다.

### 맺음말

localStorage와 sessionStorage는 웹 애플리케이션의 사용자 경험을 풍부하게 만드는 데 필수적인 도구입니다. 이들의 특징과 사용 사례를 명확히 이해하고 적절하게 활용한다면, 더욱 강력하고 효율적인 웹 서비스를 구축할 수 있을 것입니다. 다만, 민감한 정보(비밀번호, 개인 식별 정보)를 클라이언트 측 저장소에 직접 저장하는 것은 보안상 위험할 수 있으니 항상 주의하시기 바랍니다!
